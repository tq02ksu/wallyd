# 产品定位与套件化约束

> 配套：[[architecture|架构设计]]、[[hardware-selection|硬件选型与采购]]、[[risk-assessment|风险清单]]。
> 来源：2026-09-12 与用户的方案讨论（口述决策）。推断与未验证项均已标注，**非外部资料**。

## 1. 定位（2026-09-12 确定）

- **本质**：是一个**平台**，不是「一个机器人成品」。
- **形态**：以**套件形式对外销售**，不是单纯的「DIY 复刻指引」。
- **目标用户**：愿意按引导操作电脑、但**不具备动手工具能力**的普通用户。
- **门槛分配**：
  - 硬件：**零专用工具**。用户侧装配只有「插、拧、贴」三种动作。
  - 软件：**门槛可以略高**，由 Agent 引导用户完成。

### 1.1 平台 vs 成品（核心区分，2026-09-13 明确）

> 这是本项目最根本的定位，也是与「网上一大堆成品」（见
> [[macmini-robot-precedents|已有先例盘点]]）拉开差距的关键。

- **成品思维**：做一个「会动的机器人」，功能写死，用户拿到手只能用它预设的能力。
- **平台思维**：做一个**可二次开发、可定制扩展的底盘 + 智能底座**。用户拿到的是
  「能力底座」，可以像搭积木一样往上面加东西——**加个水桶就能浇花，加个托盘就能送水杯，
  加个传感器就能巡逻**。价值不在「机器人本身」，而在「它能长成什么」。

三个维度把「平台」落成可操作的东西：

1. **硬件开放**：零焊接 + 统一 USB 总线，外设「插上即用」（见 [[architecture|架构设计]] §3.5）。
   扩展件（水桶、托盘、传感器、机械臂）走同一条 USB/结构接口，不需要专用工具。
2. **软件开放**：Agent 引导 + MCP 工具注册（见 [[architecture|架构设计]] §8.2），
   新外设接入 = 注册一个新工具，Agent 自动学会用它——**软件门槛被 Agent 抹平**，用户无需懂编程。
3. **二次开发**：主 Agent 采用开源的 Codex Harness（许可证待核实）→ 社区可复刻、改造、再分发；
   宿主侧代码以 TypeScript 为主（见 [[architecture|架构设计]] §6.4）。

**一个平台的「浇花水桶」例子**（用户 2026-09-13 提出，作为平台的典型场景）：
> 用户给底盘加一个水桶（成品件，插/拧/贴即可），注册一个「浇水」工具，Agent 就能
> 按土壤湿度或定时，控制机器人走到花盆边浇水。浇花不是「预装功能」，而是
> **平台允许用户自己长出来的能力**——这才是平台区别于成品的价值所在。

**由此推论的产品原则**：
- 底盘和「智能底座（Mac mini + 本地大模型 + Agent）」是平台的核心，必须做得极稳、极开放。
- 具体应用（浇花、送物、巡逻）是**生态**，由用户和社区在平台上长出来，套件方不预置死。
- 卖点不是「我有个会浇花的机器人」，而是「**我有个能变成任何你想要的机器人的底座**」。

### 关键判据

> 软件门槛可以被 Agent 抹平，硬件工具门槛不能——没有 Agent 能替用户点焊。

因此「零焊接、零专用工具」是**硬约束**，「软件易用性」是**软约束**。

**工具基线**：用户会 DIY 功放、有电烙铁，但**没有点焊机**。连爱好者都到不了的工具，
不应要求普通用户具备。校准原则：**你自己的工具箱，就是目标用户工具箱的上界。**

## 2. 套件模式下的角色重分配

| 工序 | 用户侧 | 套件方（用户）侧 |
| --- | --- | --- |
| 点焊 / 焊接 | ❌ 禁止 | ✅ 允许（工厂工序） |
| 结构组装 | 拧螺丝 | 预制件 |
| 接线 | 插接插件（防呆） | 预制线束 |
| 固件 | — | 预烧录 / 一键刷写 |
| 软件安装 | 按 Agent 引导操作 | 一键安装脚本 |

推论：**凡是需要工具的地方，都要先变成成品件**。设计者的工作就是把这些工序从用户侧
搬到成品侧。副作用是收益：需要焊接的地方往往也是易出错、难调试的地方，这条约束会自动
把方案推向模块化成品，而模块化成品同时更好复刻、更好维护。

### 逐项成品化要求

| 部件 | 要求 | 要避的坑 |
| --- | --- | --- |
| 电池 | 官方工具电池包 + 原厂充电器 | 自制 18650 组（见 §3） |
| 电机 | 带线束的 42 步进电机（自带 2.54 杜邦头） | 光板电机需自行焊线 |
| 驱动板 | TB6600 步进驱动器选「排针已焊 / 带端子」 | 光板需自行焊排针 |
| 主控 | ESP32-S3 开发板，排针已焊 | 光板 / 需自行焊针 |
| 电源分配 | 带螺丝端子的 DC-DC 模块 | 手工焊分电板 |
| 线束 | 成品端子线 + 不同型号插头做防呆 | 让用户按图接线，最易接错 |
| 结构 | 铝型材 / 打印件 + 螺丝 | 需要钻孔、攻丝 |

**受影响的既有方案**：

- 步进电机 + TB6600 方案（[[hardware-selection]] §1/§2）：TB6600 驱动器多为带螺丝端子成品，
  装配相对简单；42 步进电机带 2.54 杜邦头，符合成品化约束。
- 「统一走 USB」总线（[[architecture]] §3.5）**符合**该约束，保留——它把接口复杂度封进了
  成品驱动里。

## 3. 电池方案结论

**采用成品电动工具电池包（如大艺 20V 平台，5S 结构）+ 原厂充电器**，不作为用户侧的自制
3S 18650 组方案。

理由：

1. 零焊接；用户对「工具电池换包」的动作已高度熟练。
2. 内置 BMS、有认证、有品牌售后；出问题可整包更换。
3. 对套件方而言，等于把电池的安全与合规责任转移给电池品牌方。

**参数对齐**：大艺 20V = 5S（满电 21V / 标称 18.5V）→ 需 **5S→12V 大电流 buck**
才能喂 12V 逆变器（21V 直连会烧；24V 逆变器的低压保护在 20–21V，与 5S 放电区间冲突，
会提前保护）。大电流 buck 另有益处：给逆变器稳定 12V，而非随电池从 21V 掉到 15V。

**采购禁用项**：¥60 级「15 节」白牌电池包。15 颗真电芯的物料成本即 ¥90–300
（二三线 2000mAh ¥6–9/颗；一线 2600mAh ¥12–20/颗），售价低于物料成本必然来自
虚标节数 / 拆机次品电芯 / 假保护板。**价格可倒推物料成本——锂电芯有硬性原材料成本下限。**

**验证方法（若仍要采购廉价包）**：

1. 恒功率放电实测 Wh（容量测试仪 ¥100–200，或功率计 + 已知负载）——唯一可靠判据。
2. 称重初筛：20V 平台 15 颗真芯含壳约 700–850g（配重块会削弱此判据）。
3. 测内阻（单节 >50mΩ 属老化）。
4. 配自己的低压截止（3.2V/cell）与保险丝，不依赖来路不明的保护板。

**待验证**：

- [ ] 工具电池包能否通过取电座端子充电（BMS 是否放行第三方充电、是否需 NTC/ID 引脚）
- [ ] 取电座能否直接放电（部分包需握手才允许输出）
- [ ] 30–40W 持续放电下的温升与 BMS 保护行为（工具电池按间歇工况设计）
- [ ] 工具包 BMS 欠压保护后是否需要官方充电器复位（影响移动场景可用性）
- [ ] 5S→12V 大电流 buck 的选型（150W 级，¥50–100）

## 4. 自动回充坞（保留，但充电路径待定）

自动回充由套件方自行实现（有专业人员支持），**不作为用户侧门槛**，因此保留在功能目标中
（[[architecture]] §1）。

**但存在一个架构冲突**：自动回充要求机器人能自行把电充进去，而「成品工具电池包 + 原厂
充电器」的工作方式是「人把电池拔下来插到充电器上」。

三条路径，取决于 §3 的验证结论：

1. **坞站直接给电池包充电**（走取电座端子，BMS 放行）→ 坞站 = 带充电电路的托盘，最简单。
2. **放弃自动回充**，退化为「坞站供电 + 人工换包」→ 保留热插拔，砍掉对接机构。
   （扫地机做了二十年，回坞成功率仍不完美；¥400 级平台做对准 + 触点是最坑的功能之一。）
3. **改用自制电池包**（焊接变为套件方工序）→ 回充最好做，但锂电产品的安全与合规责任
   全部由套件方承担。

**倾向**：优先路径 1；验证不通则走路径 2。路径 3 仅在回充是核心卖点时考虑。

**路径 1 的实现方式**：坞站侧做 Power Path（坞站供电时母线由坞站供，电池支路经理想二极管
截止，只保留充电通路），使电池成为「支路」而非「母线」。拓扑、器件清单与验证步骤见
[[power-architecture|电源架构（12V 稳定电源 + 逆变器 220V/100V）]]。

**套件化要求**（demo → 套件的最大跳跃是**一致性**，不是功能）：

- 对准公差必须锁在结构里：漏斗形导向、浮动触点、大容差触点，而不是靠人手调。
- 必须做失位重试，以及失败后人类可读的提示。
- 把专业能力花在「一次性把公差锁进结构」，而非「调好一台」。
- 回坞后进入休眠、不驱动电机，再由坞站充电——避免「边充边用」的 BMS 限制问题。

## 5. 合规与商业（套件销售的新增项）

**合规**（销售前需确认，非工程问题）：

- 锂电池运输：UN38.3 报告 + MSDS；多数快递对锂电有限制。
  **规避方式：套件不含电池**，说明书中指定用户自行购买官方工具电池包——同时规避运输
  限制与电池质保责任，且用户可自行换新。
- 220V 逆变器整机可能涉及 3C 认证。
- WiFi/蓝牙模块建议采用已认证模组（SRRC）。

**成本模型变化**：BOM ≤ ¥400 由「硬约束」降级为「研发期目标」。套件售价 =
BOM + 装配人工 + 损耗 + 退货率 + 售后风险 + 认证摊销 + 平台抽成。

**目标客户与卖点**：套件不含 Mac mini，目标客户是**已有 Mac mini 的用户群**，
卖点即「让你的 Mac mini 长出身体」。
