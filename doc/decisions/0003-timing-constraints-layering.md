# ADR-0003 时间约束分层已成立——原地保留，只补两个跨层参数

> **层与模块的统一口径见 [[../layers-and-modules|层与模块关系（唯一口径）]]**——本条只负责**时间维度**
> 那一段。时间尺度划成三段（微秒–毫秒 / 10–100Hz / 秒–分钟），它与执行位置的 4 层（L1 固件 / L2 进程内
> 模块 / L3 进程 / L4 交互面）是**多对一**关系：
> L2 与 L3 共同落在「10–100Hz / 秒级」这一段里，**不要把「3 段」当成「3 层」**。

## 背景

用「时间约束决定执行位置」这条判据复核当前分层是否合理。项目已有可用的实测数字
（`communication-protocol.md` §9、`firmware/robot_server_v2.py` 头部常量注释），
本次评估的目标是**校验**而非重新设计——先把已有数字摆齐，再看哪里真正没有结论。

现状分层（已实现，非设想）：下表是**按任务**列的落点，**不是层的清单**——
六行任务中第 2、3、5 行都是 ESP32 内部节拍的不同侧面，**同属 L1 固件这一层**。

| 任务 | 时间要求 | 现有归属 | 依据 |
| --- | --- | --- | --- |
| 生成 STEP 脉冲 | 微秒级、不可打断 | ESP32 固件（软件方波，`MAX_RATE=1500` pps） | `robot_server_v2.py` |
| 脉冲分片推进 | 每 `TICK_MS=20` 推进一片 | ESP32 主循环 | 同上（v2 相对 v1 的关键改动） |
| 串口轮询（为可打断） | 每 `POLL_EVERY_STEPS=24` 步 | ESP32 脉冲循环内 | 实测：8 步/次会吃 20% 时间 |
| 心跳看门狗 | `HEARTBEAT_TIMEOUT_MS=300` | ESP32 本地兜底 | §3.3；实测 420ms 内停机 |
| `stop` 响应 | 最坏 ~20ms | ESP32（随脉冲循环轮询） | 常量注释：24 步 ≈ 20ms@1200pps |
| 丢步判断 / 标定 | 10–50Hz，需上下文 | robotd（**L3 进程内的 L2 模块**） | ADR-0002 |

## 决策驱动

- **判据 P1（时间尺度）**：必须在本地闭环、毫秒级 → 固件（**L1**）；10–100Hz → Runtime（**L3 进程内的 L2 模块**）；秒级需语义 → 应用层（**L3 的 agentd + L4**）。
- **已有实测**：`velocity` 5Hz + 300ms 阈值**实测有效**（停心跳后 420ms 内自主停机）。
- **可维护性**：跨层参数（如频率）若不写死，两侧实现会各自假设，产生难查的偏差。
- **现状纪律**：项目已声明「引脚口径单一事实源 = 电气架构 §5.2」，时间参数应类比处理。

## 考虑的选项

- **A. 重新分层**：把运动规划上移或下移。**否决**——现有分层已被实测支撑，无证据表明放错层。
- **B. 原地保留 + 补文档**：分层不动，只把「已隐含在代码里」的跨层参数显式成文。
- **C. 不动任何东西**：继续让参数散在代码注释与协议文档中。

## 决定

选择 **B**。复核结论是**分层本身合理，不需要改**；真正缺的是两个**跨层参数没有单一归属**：

1. **速度指令更新频率**：现状是协议 §3.3 写「≥5Hz」、固件 `TICK_MS=20`（即 50Hz 内部节拍）、
   ADR-0002 写「修正 10–50Hz」——三处数字并存但没有一处声明「以哪个为准、为什么」。
   **定为：契约层要求 host 在运动意图存续期 ≥5Hz 发 `velocity`；板侧内部节拍 50Hz（`TICK_MS=20`）**
   —— 两者是**不同层**的频率，各自独立，不构成冲突，但必须在文档里显式说明是两层。
2. **打断延迟上限**：现状只有实测值（`stop` ~20ms、看门狗 420ms），没有**成文的上限承诺**。
   **定为：`stop` 端到端 ≤ 50ms；看门狗停机 ≤ 500ms**（均留实测值 2× 余量）。

同时确认一条**已被数据推翻的旧顾虑**：本项目**不用 FluidNC / G 代码**，而是自写 MicroPython
状态机固件——所以「G 代码打断延迟 ~120ms」那类 CNC 固件的参数**与本项目无关**，不应引入。

## 后果

- **好**：两个跨层参数有了单一归属，协议文档、固件、ADR 三处口径统一；分层结论有实测背书，
  不必再反复讨论「要不要改架构」。
- **坏**：`≤50ms` / `≤500ms` 是**承诺值**，装车后若实测超过就必须改这一条（走 superseded）。
- **中性**：本次不引入新硬件、不改代码，纯文档收敛。

## 怎么验证

- **看门狗**：已验（停心跳 → 420ms 内停机，见 §9）。装车后复测，断言 ≤500ms。
- **stop 延迟**：装车后实测 `stop` 端到端时延，断言 ≤50ms。测法：host 记发送时间戳，
  板侧 `motion.done` / 停脉冲事件回带 `ts` 比对。
- **两层频率不冲突**：断言——host 以 5Hz 发 `velocity` 时，板侧 50Hz 节拍**不因输入稀疏而掉速**；
  且 host 提高发送频率（如 20Hz）不改变板侧行为。这是对「两层独立」的工程检验。
