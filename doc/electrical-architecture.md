# 电气系统架构

> 本文档是电气部分的**总览**，回答「应该长成什么样、为什么」。
> 端子型号 / 防呆 / 怎么插见 [[wiring-connectors]]；能量来源（电池 / 逆变器）见
> [[power-architecture]]；步进接线细节见 [[stepper-wiring]]。

**已定结论（不再讨论）**

| # | 结论 |
| --- | --- |
| 1 | 电源 = 12V 稳压 + 逆变器供 220V/100V 给 Mac mini；坞站「边充边放」暂不做（[[power-architecture]] §9） |
| 2 | 底盘 = 2×42 步进 + 2×TB6600，各占 3 脚（`PUL/DIR/ENA`）＝ `9/10/11` + `12/13/14`（构件已购；右驱待新件） |
| 3 | 本次预留 = **+2 步进**、**1 套水泵（2 继电器 + 1 水位传感器）**、**1 套 2 轴云台** |
| 4 | 动力与信号必须用不同型号插头物理防呆（12V 插不进 GPIO） |
| 5 | 共地，但动力域与逻辑域不共电源 |

## 1. 三条原则

| 原则 | 含义 | 为什么 |
| --- | --- | --- |
| **按电压分层** | 动力 12V / 逻辑 5V / 信号 3.3V | 电压混接是最大的烧机来源，分层让错误在物理上不可能 |
| **共地不共电源** | GND 全部连通；供电轨按域分开 | 电机启停的压降与反电动势会把 MCU 拉到复位 |
| **统一接口** | 动力、信号各用固定型号插头 | 加设备只插预留口，不改主线（平台定位，见 [[product-positioning]] §1.1） |

## 2. 功率树

```text
电池包 18.5V ──[5S→12V 降压]──┐
                              ├─► 12V 主干母线（进线锁 KF 端子排；设备位出大 4P）
                              │        ├─► 逆变器 → 220V/100V → Mac mini
                              │        ├─► TB6600 ×4 → 42 步进 ×4
                              │        ├─► 继电器 ×2 → 水泵
                              │        ├─► 12V→5V ──► 逻辑轨：ESP32 / 传感器 / TB6600 共阳
                              │        └─► 12V→6V ──► 舵机云台（独立降压 + 大电容）
                              └─►（坞站边充边放：暂不做，见 [[power-architecture]] §9）
```

| 轨 | 电压 | 喂什么 | 电流量级 | 归属 |
| --- | --- | --- | --- | --- |
| 动力轨 | 12V | 步进 ×4（经 TB6600）、水泵（经继电器）、云台动力、逆变器 | 峰值 25A 级（见 §7） | 动力域 |
| 逻辑轨 | 5V | ESP32、传感器、TB6600 光耦共阳端 | 0.5–1A | 逻辑域 |
| 舵机轨 | 5V/6V | 云台舵机 | 峰值 2–2.5A/路 | 动力域（独立降压） |
| 信号域 | 3.3V | ESP32 GPIO 电平（板载 LDO 自产） | 十几 mA | 逻辑域 |

## 3. 电源域划分

核心一句话：**共地 ≠ 共电源**。三个域内部可共电源，域之间只共地。

| 域 | 包含 | 供电 |
| --- | --- | --- |
| 动力域 | 步进 ×4、水泵、云台动力、逆变器 | 12V 主干 |
| 逻辑域 | ESP32、传感器 | 5V 独立降压 |
| 信号 | GPIO 电平 | 3.3V 板载 |

落地三条：

1. 5V 逻辑轨**独立降压、独立走线**，不与电机动力混走（两者可从同一块 12V 母线取电）。
2. 调试期 ESP32 直接插电脑 USB 供电最稳；装车后走独立 5V 逻辑轨。
3. 舵机（峰值 2–2.5A/路）**单独一路降压 + 1000µF 级电容 + 独立开关**，绝不与 ESP32 共 5V。

## 4. 控制分层

```text
命令层  Mac mini（Agent / Codex）   下发 move / rotate / pump_on / gimbal
          │ USB 串口
控制层  ESP32-S3                    解析指令 → 脉冲 / 电平 / PWM
          │ 3.3V 信号
执行层  TB6600 ×4 ｜ 继电器 ×2 ｜ 舵机 ×2    + 12V 动力域
```

各层职责单一：Mac 只管决策，ESP32 只管翻译成硬件信号，执行器只管干活；出问题可逐层定位。

## 5. I/O 引脚规划（含本次预留）

### 5.1 可用引脚约束

ESP32-S3-N16R8 上**不能动**的脚：

- GPIO0 / 3 / 45 / 46：strapping
- GPIO19 / 20：USB
- GPIO26–37：Flash / PSRAM（N16R8 为 Octal PSRAM）
- GPIO43 / 44：UART0
- GPIO48：板载 WS2812 灯
- GPIO22–25：S3 上不存在

⇒ 可用：**1、2、4–18、21、38–42、47**（共 24 个）。

**模拟量的硬约束**：只有 **GPIO1–10（ADC1）** 能可靠做模拟输入。ADC2（GPIO11–20）与 Wi-Fi
驱动共用，开 Wi-Fi 时不可用（**待实测确认**）。所以水位、电流这类可能要模拟采样的量，
必须占在 1–10 上；纯数字设备（脉冲、开关、PWM）不受此限制。

### 5.2 分配表（按板上引脚**物理排布**重排，2026-10-04 依丝印图复核）

> 排法原则（用户要求）：**同一功能的所有引脚在板上连排、一个线束引完**。
> **2026-10-04 依丝印实拍图（`raw/robot/img.png`，裁切放大逐脚读数）复核**：左列可用引脚实际只有
> **两段物理连续**——
> **段① `4·5·6·7·15·16·17·18·8`（九连排）**、**段② `9·10·11·12·13·14`（六连排）**，
> 中间只隔 strapping 脚 `3/46`。此前文档把 `4/5/6/7` 与 `15/16/17/18/8` 写成「段①/段②」是
> **功能分组，不是物理断点**——`7` 与 `15` 是紧挨着的两脚。
> 右列可用为**一段**：`1·2·42·41·40·39·38`（七连排），再往下 `37/36/35` 属 Flash/PSRAM 不可用。
> 最终：**左列 = 全部执行器**（底盘 + 扩展步进 + 泵组 + 云台 + EN），**右列 = I2C + 备用**。

| 分组 | 设备 / 信号 | GPIO | 板上位置 |
| --- | --- | --- | --- |
| **底盘：左驱**（2026-10-05 定案） | PUL / DIR / ENA | 9 / 10 / 11 | 左列·段② 前三脚 |
| **底盘：右驱** | PUL / DIR / ENA | 12 / 13 / 14 | 左列·段②，与左驱连排（**全板唯一 6 连排**） |
| **扩展 E1：步进 3** | PUL / DIR / ENA | 4 / 5 / 6 | 左列·段① 前三脚 |
| **扩展 E1：步进 4** | PUL / DIR / ENA | 15 / 16 / 17 | 左列·段① 中三脚 |
| **扩展 E2：水泵组** | 水位传感器 / K1（吸） / K2（放） | 1 / 2 / 42 | 右列顶部三脚（水位在 `1`，**ADC1_CH0**） |
| **扩展 E3：2 轴云台** | 航向 / 俯仰 PWM | 41 / 40 | 右列，连排 |
| 传感器总线 | I2C SDA / SCL | 39 / 38 | 右列，连排（一二十个传感器只占 2 脚） |
| **合计占用** | | **19 脚** | |
| **剩余空闲** | | 7、18、8 ｜ 47、21 | 全部为**单脚**：左列段① 是 4+4+1 结构、必然剩 2 个（`7`、`18`）+ 末端的 `8`；`47`/`21` 是板上孤立脚 |

**逐功能连排核对**（每台驱动器各自 3 连排；剩余全是单脚，见下方说明）：

```text
 段①  4 · 5 · 6 │ 7 │ 15 · 16 · 17 │ 18 │ 8          = 9 脚（4+1+3+1+1）
      步进3 3 连排  单  步进4 3 连排   单   单

 段②  9 · 10 · 11 │ 12 · 13 · 14                      = 6 脚，排满
      左驱 3 连排    右驱 3 连排（底盘）

 右列 1 · 2 · 42 │ 41 · 40 │ 39 · 38                  = 7 连排，排满
      水泵 3 连排   云台       I2C
```

底盘左驱 `9·10·11` ✓ ｜ 底盘右驱 `12·13·14` ✓ ｜ 步进3 `4·5·6` ✓ ｜ 步进4 `15·16·17` ✓ ｜
水泵 `1·2·42` ✓ ｜ 云台 `41·40` ✓ ｜ I2C `39·38` ✓

> **为什么还有 5 个单脚**：全板同时满足「位置连＋序号连」的块只有
> `4·5·6·7`、`15·16·17·18`、`9·10·11·12·13·14`、`1·2`、`42·41·40·39·38`（+ 单脚 `8`、`47`、`21`）。
> 左列段① 长度 9、结构是 **4+4+1**，塞两个 3 脚驱动器必然剩 2 个（`7`、`18`），加末端 `8` 共 3 个；
> `47`/`21` 被板上不可用脚夹住（`48/45`、`20/19`）。**这是板子排布决定的，不是排法问题**——
> 要零碎片就必须放弃「序号连」（允许 `7·15·16` 这类位置连但跳号的块）。

**四条注意**：

1. **右边 9 个 GPIO 不是一整段**：`1·2·42·41·40·39·38`（7 连排）+ `47` + `21`（两个孤立单脚）。
   所以「底盘 6 脚 + 水泵 3 脚全放右边」**做不到位置连**——9 脚里能连成块的只有 7 个。
   另外右边「序号」在 `2 → 42` 处跳号（板上印的是 `1·2·42·41·40·39·38`）。
2. **底盘两驱落在左列段② `9–14`**：这是全板唯一一段同时满足「位置连＋序号连」的 6 连排。
3. **水位在 `1`（ADC1_CH0）**。若水位最终是**数字浮球开关**（不需要 ADC1），可把水泵换成
   `42·41·40`、云台换 `1·2`，号更连（本表按「可能要模拟采样」保守排）。
4. **`7`/`18`/`8`/`47`/`21` 是单脚备用**（成因见上）；它们只能接 1 脚设备（指示灯、按键、
   限位开关），或留给以后的单路模拟输入（`7`、`8` 是 ADC1）。

**排布依据**：本表按三条约束推导，不是逐次试出来的——① 每台驱动器 3 脚（`PUL/DIR/ENA`）；
② 同一功能的引脚**位置连 + 序号连**；③ 水位必须在 ADC1（`1–10`）。推导过程与 5 次改版的
历史只留在 git 提交记录（本表只写**当前方案**）。EN 的电气与固件策略见 §5.3。

### 5.3 步进脱机 EN：每台一条（2026-10-05 定）

**谁管 `ENA`（判据推论，见 [[architecture|架构设计]] §1）**：引脚与时序在**固件**
（P1 时间尺度 / P2 真相 / P3 后果）；Runtime 只持有策略配置（`hold_ms`、看门狗后是否脱机）；
**应用层与 Agent 不暴露**（P4 粒度）；接线核对与量静置电流用的手动开关属**调试旁路**（P5）。
固件实现见 `work/poc/firmware/robot_server_v2.py`（`work/` 不入库）。

**为什么要加**：TB6600 是恒流斩波驱动，**静止时仍按拨码档持续给线圈供电流**以维持保持力矩。
按 42BYGH47（额定约 1.5A、单相电阻 1.8Ω 量级）估算，每台静置耗散 ≈ 2·I²R ≈ 8W，
从 12V 母线看约 0.8A/台；**四台合计 16–38W（取决于电流档）**，远超 M4 Mac mini 空闲 ~7W——
**车停着不动时，步进就是整车最大的静置负载**。不接 `ENA`（悬空）= 常使能 = 一直在付这笔钱。

**排法（依图定案）**：**每台驱动器 3 根（`PUL`/`DIR`/`ENA`），四台共 12 脚；
每台各自占一个 3 连排**：

```text
 段①  4 · 5 · 6 │ 7 │ 15 · 16 · 17 │ 18 │ 8
      步进3 3 连排  单  步进4 3 连排   单   单

 段②  9 · 10 · 11 │ 12 · 13 · 14
      底盘左驱 3 连排  底盘右驱 3 连排
```

| 驱动器 | `PUL` | `DIR` | `ENA` | 备注 |
| --- | --- | --- | --- | --- |
| 底盘左驱 | 9 | 10 | **11** | `PUL/DIR` 从 `4/5` 挪来（两根重插） |
| 底盘右驱 | 12 | 13 | **14** | `PUL/DIR` 从 `6/7` 挪来（两根重插） |
| 步进3（扩展） | 4 | 5 | **6** | 未接线，零成本 |
| 步进4（扩展） | 15 | 16 | **17** | 未接线，零成本 |

**电气**：

- 每台 `ENA` 独占一条 GPIO 时，灌电流十几 mA，在 ESP32-S3 单脚能力内
  （推荐 ≈20mA、绝对上限 40mA）→ **可以 GPIO 直驱，不必加三极管**；
  实测若单路 >20mA，或将来要把两路并到一脚，再加一级 NPN。
- **极性（2026-10-05 实测，与厂商口径不同）**：`ENA−` **悬空 = 使能**（有保持电流、手拧有阻力）；
  **拉低 = 关输出**（无电流）；**拉到 3.3V 也会关**（光耦两端仍有 ~1.7V，部分导通）。
  ⇒ 本批 TB6600 的输入光耦是「**导通 = 有效**」，而"导通"包含"被 3.3V 部分驱动"这一档。
- **🔴 两态制（同时适用于 `PUL`/`DIR`）**：这三根线**只允许"拉低"与"高阻"两态，永不打高**。
  把 `PUL` 空闲拉到 3.3V 会让输入一直停在"有效"态 → 驱动器看不到边沿 → **电机完全不转**
  （本次为此排查了很久：电平量着都对、手工点 GND 能走、接上 ESP32 就不走）。
  详见 [[stepper-wiring|步进驱动接线与供电]] §2.3。
- **上电/复位默认态**：GPIO 未驱动时为高阻 → `ENA` 悬空 = **使能/持有** ——
  MCU 挂死或复位时**车不会自由滑行**（代价是那一刻继续耗电）。空闲省电由固件主动拉低脱机来做。

**固件策略（板侧状态机；上层不碰 EN，见本节开头判据推论）**：

1. **固件时序**：
   - 收到 `move`/`rotate`：先使能 → **等 10–20ms**（光耦 + 驱动器建立）→ 再发第一个脉冲；
   - 脉冲发完：**留 100–200ms** 稳定 → 再脱机（立刻脱机会顿挫甚至丢步）；
   - **有待发脉冲时绝不脱机**；
   - 心跳看门狗急停后是否脱机 = 策略项：平地默认脱机（省电不发热），坡道要保位则保留保持力矩。
2. **代价（必须一起记住）**：脱机 = 放弃保持力矩，而本车**没有编码器**、开环数步当里程计——
   空闲期间被外力推动（USB 线拽、手碰、坡道溜）会**静默丢位姿且无法发现**。所以只在 idle 释放，
   并把「空闲期间可能被推动」记为已知风险（[[risk-assessment|风险清单]]）。

**连带影响**：

- **每台驱动器一个 3 连排，且底盘两驱占了全板唯一的 6 连排**（段② `9–14`）；
  扩展两台落在段① 的两个 4 连排里（`4·5·6`、`15·16·17`），段① 因此剩 3 个单脚（`7`、`18`、`8`）。
- **水泵/云台/I2C 排满右列 7 连排**（`1·2·42` / `41·40` / `39·38`），`47`、`21` 是板上孤立脚。
- 外部 JTAG（`39–42`）里 `41`、`40` 给了云台、`39` 给了 I2C → **外部 JTAG 不可用**；
  ESP32-S3 **自带 USB-Serial-JTAG**（走 USB 口），故可接受。
- **更彻底的路**：换 **TMC5160** 这类带 standstill 电流衰减 + StallGuard（无感归零）的驱动，
  能同时解决省电、保位与「没有编码器」三件事，但硬件要换、成本上去。

### 5.4 三条限制（必须知道）

1. **4 个步进 ≠ 4 轴同时动。** 当前板侧脚本 `robot_server_steps.py` 的 `drive_steps()` 是
   **顺序发脉冲**（先左轮、再右轮），连底盘「走直线」现在都是分两段走的（会先转再走）。
   - 需求是「逐个动」（一次只动一两个轴）：4 个步进没问题，只算 GPIO，不用换方案。
   - 需求是「多轴同时 / 插补」（走直线、机械臂联动）：MicroPython 的 `bitstream` 做不到，
     要换 **ESP-IDF（RMT / MCPWM 硬件通道）**，或加 **I2C / 串口多轴驱动板**（如 TMC 系）。
   - 这是本项目**第一个要做的技术决定**：底盘走直线是否算硬需求。
2. **继电器只碰 IN 脚。** 水泵是感性负载（0.8–3A，启停浪涌 2–3 倍），GPIO 直驱必烧。
   GPIO → 继电器模块 IN，水泵由触点通断，触点侧加续流 / RC 吸收。
3. **舵机供电不走 ESP32。** 信号 3.3V 走 GPIO（LEDC PWM，任意 GPIO 都行，S3 共 8 通道），
   供电必须独立降压 + 大电容。

## 6. 扩展接口

每个扩展位 = **1 组电源插头 + 1 组信号插头**，型号不同、物理防呆。

| 扩展位 | 电源 | 信号 | 设备 | I/O |
| --- | --- | --- | --- | --- |
| EXT-1 | 大 4P ※ | 杜邦 | 水泵（经继电器） | **GPIO1（水位，ADC1_CH0）/ 2 / 42（继电器）——右列顶部三连排** |
| EXT-2 | 大 4P | 杜邦 | 步进3 / 步进4（TB6600 #3 / #4） | 步进3 `4·5·6`、步进4 `15·16·17`（各含 ENA，左列段①） |
| EXT-3 | 大 4P（舵机要 6V 则本地降压） | 杜邦 | 2 轴云台 | GPIO41 / 40（右列连排） |
| EXT-4 | 大 4P | 杜邦 | 未来设备 | 单脚 `7` / `18` / `8`（左列）＋ `47` / `21`（右列） |

> ※ **大 4P = 电脑电源的 4-pin 头**：一个头给齐 12V + 5V + 双 GND，自带防呆插不错正反，
> 所以 TB6600 的 `VCC/GND` 和共阳的 5V 从同一个头取；弱电信号一律走杜邦。
> 大 4P 的 12V 只有 1 个脚，水泵等带浪涌的大电流单路若超出其载流，该位改为锁在
> 分电板的 KF 端子排上。

**三不原则**：不改主线（只插预留口）、不重布线（一设备一根适配线）、不超功率
（接入前先核算 §7 余量）。

## 7. 功率余量核算（按本次扩展）

| 负载 | 12V 侧估算 | 备注 |
| --- | --- | --- |
| Mac mini（经逆变器） | 14.7A | 按 150W 输入估算；若选 200W 机型按 ≈20A 计 |
| 步进 ×4 + TB6600 ×4 | 4–6A | 单机 1.5A 估；满载、间歇 |
| 水泵 | 0.8–3A | 启动浪涌 2–3 倍 |
| 云台舵机 ×2 | ≈2.5A | 2–2.5A/路 @6V 折算到 12V 侧 |
| 逻辑轨（ESP32 + 传感器） | ≈0.5A | |
| **峰值合计** | **≈25A 量级** | 非全部同时满载 |

结论：

- `5S→12V` 降压模块要按 **≥30A** 选；否则**逆变器与动力分两路**从电池取电。
- 电池包 BMS 的 30A 级浪涌风险被放大 → 逆变器**软启动 / 预充电阻**从「建议」升级为
  「必要」（与 [[power-architecture]] §5 风险 1 同源）。
- 母线 12V 前置保险按峰值 + 余量选（见 §8）。

## 8. 保护与可靠性

**四级防御**

| 级别 | 防线 | 防什么 | 用什么 |
| --- | --- | --- | --- |
| L1 物理防呆 | 强电大 4P、弱电杜邦，插错插不进 | 12V 怼 GPIO、正反接反 | 大 4P 防反插；杜邦无防呆，靠 L2 兜 |
| L2 颜色 + 丝印 | 标识极性与功能 | 方向 / 功能接混 | 红=12V+、黑=GND、橙=5V、蓝=STEP、绿=DIR |
| L3 保险丝 | 母线前置过流断开 | 短路 / 过流烧机 | 12V 母线前置 5A 保险或 PPTC |
| L4 软件限流 / 软启动 | 程序层限流、分级上电 | 浪涌触发 BMS 保护、堵转 | 软启动、电流采样、加速度限制 |

L1 是根本（事前杜绝），L2/L3 是补救。**必配**：母线 12V 前置保险、水泵续流。
**建议**：逆变器 / 水泵软启动。

**可靠性要点**

- 12V 主干在 TB6600 旁就近并 100–470µF 电解，吸收电机回头电流。
- 信号线与动力线分开走，尽量十字交叉、不平行；电机线用双绞或屏蔽。
- TB6600 要通风，别贴死在封闭壳内；逆变器满载约 20W+ 废热，封闭车内要做散热。
- 大电流路径（主干、水泵）锁在 KF 螺丝端子上；杜邦一律不做电源。
