# 可行性评估与技术风险清单

> 配套：[[architecture|架构设计]]、[[hardware-selection|硬件选型与采购]]。
> 本文记录方案的可行性结论与风险项，用于逐条验证与跟进。

## 1. 总体结论

**有条件可行**。软硬件均为成熟元件拼装，无未知科学难题；真正的成败手是
**R1（电池+逆变器供电 Mac mini）** 与 **R2（2kg 负载拖动）** 两关，
用 ~¥300 即可先验证，宜先花小钱定生死再铺开。

## 3. 风险明细

### R1 锂电池 + 逆变器稳定供电 Mac mini（方案性死结）

- **等级**：🔴 最高　**概率**：中高
- **描述**：Mac mini 是交流供电，必须「电池(DC)→逆变器(AC)」。廉价纯正弦逆变器在
  重载下波形劣化，可能欠压重启或伤 Mac mini 电源；跑本地模型 ~30–50W，续航也吃紧。
- **验证方法（PoC）**：买纯正弦 200W + 成品 5S 工具电池包（配 5S→12V buck，见
  [[product-positioning|产品定位与套件化约束]] §3），台式测试：①冷启动 20 次不重启；
  ②满载跑 30 分钟不欠压；③实测功耗算真实续航。
- **缓解措施**：品牌逆变器 + 2–3 倍功率余量 + BMS 低电保护。
- **退路**：Mac mini 固定在底座拖极短电源线（半移动），或 12V 直流直供改造（拆机、高风险、慎）。
- **状态**：- [ ] 未开始

### R2 2kg 负载拖动（扭矩/速度）

- **等级**：🔴 高　**概率**：中
- **描述**：整车 ~2kg（Mac mini 670g + 逆变器 + 电池 ≈ 1.2kg 起步），42 步进电机（42BYGH47，0.55N·m）
  需配合 TB6600 细分驱动；步进扭矩随转速下降明显，高速时扭矩衰减需实测。
- **验证方法（PoC）**：42 步进电机 + 2kg 配重，测启动扭矩、爬坡（3–5°）、轮速（步进最高转速）。
- **缓解措施**：加大电流（TB6600 支持大电流）/ 提高驱动电压 / 减速比；若扭矩不足，换 57 步进。
- **状态**：- [ ] 未开始

### R3 自动充电机械对接精度

- **等级**：🟡 中　**概率**：中高
- **描述**：回坞时触点对准、接触可靠、IR 引导精度——纯机械工程，靠迭代。
- **定位变更（2026-09-12）**：自动回充当由套件方实现（有专业人员支持），**不构成用户侧
  门槛**，保留为功能目标。但改用成品工具电池包后，「坞站如何给电池包充电」出现架构
  冲突，见 [[product-positioning|产品定位与套件化约束]] §4。
- **验证方法（PoC）**：分两步——先「手推能充」，再「IR 自动对接」。
- **缓解措施**：磁吸自动吸附对齐 + 弹簧针（pogo pin）+ 大触点容差。
- **状态**：- [ ] 未开始

### R4 本地模型实时性（尤其 VLM）

- **等级**：🟡 中　**概率**：中
- **描述**：VLM 是「慢而通用」的路径，做实时视觉偏慢；多模型共存的内存 / 速度余量未测。
- **实测（2026-10-06，本机 Mac mini `Mac16,10` / Apple M4 / 24GB，5 张 COCO val2017 公开图）**：
  - **慢路径（MiniCPM-V 4.6 4bit / MLX）**：**0.84s / 帧**（min 0.78 / max 0.90）——prompt「用一句话
    描述这张图片」、输出 16–18 token ⇒ **≈20 tok/s**；服务空载预热 **2.1s**。按此线性外推，100 token
    的回答 ≈5s ⇒ 「1–3s/帧」对短回答偏保守、对长回答偏乐观。
  - **快路径（macOS 自带 Vision，零下载零许可）**：**4–20 ms / 次**——分类 6–13ms、动物检测 4–7ms
    （带框）、人体 3.7–7ms、人脸 3–8ms、前景掩码 13–21ms。**比 VLM 快约 100–200×**。
  - 复现：脚本与完整结果见 [[eval/vision-latency|视觉延迟实测]]（`projects/robot/eval/`，已入库）；
    测试图是 COCO val2017 公开图，缓存在 `work/eval/`（二进制不入库）。摘要见 [[architecture]] §10.3。
- **仍未测**：主 LLM + VLM + ASR + TTS **共存**时的内存与延迟余量（单模型数据已够解除「能不能用」的疑问）。
- **缓解措施**：4bit 量化 + 降分辨率 + VLM 按需调用（定时拍照，非逐帧流）+ **实时回路走系统检测器**
  （系统 Vision 给不出所需类别时再引 YOLO）+ TTS 预合成。
- **状态**：- [x] 部分完成（2026-10-06：单帧延迟已实测；共存余量未测）

### R5 步进电机丢步与定位精度

- **等级**：🟡 中　**概率**：中
- **描述**：步进电机为**开环定位**（无编码器闭环），若负载过大、速度过快或供电不足会**丢步**，
  导致位置累计误差；低速受扭矩衰减影响也需控制。
- **缓解措施**：选足够扭矩的电机 + TB6600 细分驱动稳定供电；必要时加末端限位或编码器校正；避免高速启停。
- **状态**：- [ ] 未开始

### R6 Codex Harness macOS 本地部署

- **等级**：🟢 低　**概率**：低
- **描述**：安装、自定义工具注册（app-server 动态工具 / MCP）、与本地 MLX 端点对接，未实测但预期可行。
- **验证方法（PoC）**：本地跑 Codex Harness，注册一个自定义工具，挂载本地 MLX 端点跑通，并接上审批流。
- **状态**：- [ ] 未开始

### R7 USB 枚举/热插拔稳定性

- **等级**：🟢 低　**概率**：低
- **描述**：macOS 下 USB 设备掉线/重连、端口号变化。
- **缓解措施**：`serial.tools.list_ports` 按 VID/PID 自动识别 + 重连逻辑 + launchd 拉起。
- **状态**：- [ ] 未开始

## 4. Go/No-Go 验证顺序

1. **第一步（定生死）**：R1 逆变器供电 PoC —— 不过则全案停。
2. **第二步（定能力）**：R2 拖动 2kg + R5 里程计。
3. **第三步（定体验）**：R4 模型实时性 + R6 Codex Harness 部署。
4. **第四步（定闭环）**：R3 自动充电（可迭代、不阻塞主线，放最后）。

## 5. 决策记录

- **确定项（由硬约束决定）**：USB-only、ESP32 分层、纯正弦逆变器、全本地模型。
- **业务优先（2026-09-18）**：核心目标 = Codex 通过 USB 控制 42 步进 + TB6600 小车。
  编译/框架（MicroPython/Arduino/ESP-IDF）**后置为非阻塞项**，先跑通「USB 高层指令 → 电机转动」
  业务闭环，再回头定框架（见 [[architecture]] §5.3）。
- **待验证假设（可能推翻当前推荐）**：R1 供电、R2 电机、Codex Harness 本地部署与模型接入、各模型实测。
