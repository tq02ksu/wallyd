# agentd 详细功能与用户界面设计

> **这是目标设计，不是功能完成声明。** 本轮只设计，不改运行时代码与机器可读契约。
> 总体边界沿用 [architecture.md](../architecture.md) §7、§10.6；
> 实施顺序与完成标准见 [开发任务清单](agentd-development-plan.md)。
> 具体路由、事件名和参数在本文中均为候选；实现前必须进入 agentd 自己的契约。

## 1. 产品目标与现状

agentd 是机器人的“大脑与管家”：接收请求、理解意图、组织任务、管理高级模型和审批，
并把系统正在做什么、为什么没有继续、过去发生了什么，用普通人读得懂的方式展示出来。

**日常使用只需回答三个问题：现在正常吗？正在做什么？刚才发生了什么？**
模型接入和底层排障放在次级入口，不把开发调试面板当作产品首页。

### 1.1 已有与缺口（2026-10-23 代码基线）

| 面向 | 已有 POC | 本方案要补齐 |
| --- | --- | --- |
| 执行 | `codex exec --json`、单活动 run、中断、工具事件计数 | 受管 app-server、会话、确定性快速路由、明确终态 |
| 审批 | 内存 Map、HTTP 挂起、人工回填、超时拒绝 | 持久审计、语音确认、参数绑定授权；日常页面只观察 |
| 状态 | agentd 快照、每 2 秒探测 robotd | 来源与新鲜度、模型/音频观测、故障降级与重连对齐 |
| 历史 | 内存 runs、当次 JSONL、实时 WS | 重启仍在的任务/事件、筛选、关联与可读摘要 |
| 配置 | CLI/环境变量、继承 Harness 环境 | UI 配置高级模型、验证、版本化生效与回退 |
| 界面 | 返回现有 `panel.html`，主要是硬件与能力调试 | 独立日常界面；原调试面板保留维护入口 |

证据（现状入口；此表描述的是**当时 POC 的现状**，POC 已于 2026-10-23 整体删除）：
[agentd/src/agentd/cli.ts](../../agentd/src/agentd/cli.ts)、[agentd/ui/index.html](../../agentd/ui/index.html)、
[agentd/src/agentd/service.ts](../../agentd/src/agentd/service.ts)。POC 的 `exit_code=0` 不等于物理任务成功；
仅结束 Agent Loop 不能证明 robotd 的任务已经完成。

### 1.2 本期范围

首版交付：总览、文本/语音意图入口、单活动任务、快速路由、复杂任务 Harness、
高级模型配置、语音审批观测、可持久查询的历史、故障与中断。

后续扩展：持久日程、主动提醒、经用户确认的长期记忆。导航、避障、回充、浇水
不是 agentd 独立实现的能力；robotd 未发布的动作不展示为可执行。
首版不做多 Agent 并行、远程访问、插件市场或大而全的监控平台。

## 2. 职责与模块

```text
用户文本 / robotd 语音事件
            |
       输入去重、时效与来源检查
            |
       明确短指令？ ---- 是 ---> 确定性快速路由
            |                         |
           否                         |
       Session -> Codex app-server -> 工具请求
                                      |
                         权限 / 参数 / Approval
                                      |
                       MCP 客户端 -> robotd / modeld
                                      |
                  任务结果、状态与事件 -> Store -> UI
```

| 模块 | 具体责任 | 不负责 |
| --- | --- | --- |
| Input / Router | 接收文本与最终 ASR、去重、STOP 优先、澄清缺参 | 不凭模糊话语猜目标、不直接驱动硬件 |
| Session / Run | 对话上下文、步骤、取消、任务关联、最终结果 | 不以模型声称“完成”覆盖执行证据 |
| Harness Supervisor | 启停 app-server、协议握手、流式事件、中断、崩溃隔离 | 不把原始 Harness 协议泄露给 UI |
| Provider Config | 高级模型配置、协议适配、兼容性检测、版本管理 | 不接管 modeld 的模型加载/视觉参数 |
| Approval | 唯一审批结论、语音确认窗口、授权与审计 | 模型不能批准自己；UI 不是日常批准入口 |
| MCP / Observation | 公开能力调用、订阅 robotd、快照对齐、观测投影 | 不读取 robotd 数据库、代码或生成物构造接口 |
| Store / Event Projection | 会话、任务、配置、审批和语义事件；分页与摘要 | 不持有第二份可写 RobotState |
| Panel API / UI | 展示、提交请求、设置、历史查询 | 不将原始日志当作唯一用户解释 |

agentd 保持 TypeScript，robotd 的 Python 迁移不影响这个分工。
目录归属及契约隔离遵循已接受的 [ADR-0007](../decisions/0007-agentd-robotd-boundary.md)；
决策已确认不等于改造已落地，本文不另行冻结新的架构决策。

## 3. 功能行为

### 3.1 输入、快速路由与会话

**“是否为明确短指令”由 agentd 内部的 Input / Router 判断**，不是由 robotd 判断，
也不要求每次调用高级模型做分类。先执行已注册规则的表达匹配、参数校验与上下文前提检查；
只有唯一匹配且条件满足时才走快速路径。无匹配交给 Harness 理解；缺参、歧义或规则冲突时
进入澄清，不按“第一条命中”执行。判断依据是明确规则和当前证据，不是模型自报置信度。

- 文本提交返回请求 ID；重复提交同一幂等键只产生一个 run。第一版活动 run 上限为 1，
  新请求遇忙返回冲突，由用户决定是否取消当前任务，不排队后突然执行。
- ASR 只消费最终转写；用来源会话、事件 ID 和输入有效期去重，重连补历史不能触发动作。
  页面清楚显示“听到：……”与“理解为：……”，两者不混在一起。
- “停止”走确定性优先路由，不等模型；“跟我走”只有目标可靠绑定且能力已发布时才映射
  `robot_follow`，否则澄清。“帮我看看这是什么”等开放问题交给 Harness。
- 快速路由也经过同一权限与审批门，不因为跳过模型就免审批；不支持的指令解释缺少什么能力。
- 会话可新建、查看和继续；重启后显示历史，但不自动恢复动作。继续旧会话先重新取得当前状态，
  历史工具结果标注为历史证据，不能充当当前可执行条件。
- 不展示模型私有思维链。展示的是面向用户的计划摘要、实际工具动作与执行结果。

#### 快速路由的增量扩展

首版只注册少量高确定性指令；规则不要求一次列全。每条声明稳定 ID、版本、支持的表达、
参数提取与校验、上下文前提、目标公开能力以及测试样例。审批要求从能力契约取得，
规则只能收紧，不能降低。新增规则经过正例、反例、歧义与旧规则冲突测试后版本化启用；
任务事件记录实际命中的规则 ID/版本，停用或回退不改写历史。STOP 保留受保护的优先路径，
扩展规则不能覆盖或延迟它。

**首版支持开发维护时补充规则，不开放运行中的模型直接改写路由。**
后续可让 agentd 根据未匹配请求提出候选表达，走“脱敏样例 → 候选提案 → 校验与回归
→ 人工确认 → 版本化启用”流程；候选阶段不得执行。新表达只能映射到已发布能力，
新增硬件能力仍由 robotd 契约与实现承接。该自助扩展是后续项，不作为首版已具备的能力。

#### 3.1.1 实现记录（2026-10-24：快速路由已落地）

落点 `agentd/src/agentd/router.ts`，`service.ts` 的 `/api/run` 用它替换了原先写死的
`route: 'harness'`（在此之前所有请求都标成「交给模型」，快速路由等于不存在）。

**首版规则**：只有 `stop_robot@1`（`robot.stop`，`protected: true`）。

**判定顺序（顺序本身就是安全设计）**：

1. **否定/疑问守卫**先跑：`不要|不用|别|甭|无需|不必|能不能|可不可以|可以吗|是不是|要不要`
   命中即**返回无匹配**（交给 Harness）。「不要停」被 stop 规则吃掉会执行一次真实且无法撤销的停止。
2. **受保护规则单独一轮**：命中即决，扩展规则不能延迟 STOP。
3. 其余规则求候选集：0 条 → Harness；1 条 → 查前提；≥2 条 → **澄清**（列出候选，不按第一条执行）。

**几个刻意的取舍**：

- **不做子串匹配**。「停止跟随」若按子串匹配会被 stop 吃掉，实际是「停止跟随」这条另一个指令；
  现在这种带未知尾巴的输入一律交给 Harness。
- **审批标志不写在规则里**。审批只从能力契约取（`CapabilityInfo.requiresApproval`），
  规则不能降低它。`MatchResult.matched` 里也**故意没有** `requires_approval` 字段，
  免得执行层误以为「路由命中 = 不用审批」。
- **能力表未知（`null`）时不拒绝**。还没探测到不代表没有；由执行层在真正调用时报错。
  但能力表已知且**没有**目标能力时 → 澄清并说明缺什么。

**契约同步**：`RunAccepted` 补了 `ambiguous`（候选规则列表）与 `clarify`（`question` / `missing`）；
`route` 枚举的 `claried` 拼写错误改为 `clarified`（实现里一直是正确拼写，是契约写错了）。

**实测**（`robotd --sim` + `agentd`）：

| 输入 | route | fast_rule | 结果 |
| --- | --- | --- | --- |
| 停止 | `fast` | `stop_robot@1` | `accepted → executing → succeeded`，步骤 `执行 robot_stop` 完成，工具调用 `robot_stop` 成功 |
| 停一下 | `fast` | `stop_robot@1` | 同上 |
| 不要停 | `harness` | — | 否定守卫生效，robotd 未收到任何 stop |
| 帮我看看这是什么 | `harness` | — | — |

测试 `agentd/tests/unit/router.test.ts`（33 项，反例多于正例：否定、疑问、前缀污染、冲突、歧义、前提不满足）。

**执行纪律（`service.ts` 的 `executeFastRun`）**：

- **审批只从能力契约取**（`CapabilityInfo.requiresApproval`）。首版唯一规则 `robot_stop` 不需要审批；
  将来加需要审批的规则时，这里落到 `waiting_confirmation` 而不是直接执行——规则不能降低审批门。
- **能力缺失 → `failed` 并写明「未执行任何动作」**，不静默成功。
- **步骤与工具调用都落库**：只有状态没有步骤会出现「succeeded 但看不出执行过什么」。
- **失败如实记 `failed`**：不能把「没执行成」显示成「已停止」。

> 这里踩过一个真实缺陷：规则最初把能力写成 `robot.stop`（契约的 operationId 风格），而能力表用的是
> **工具名 `robot_stop`**（`contracts/generated/mcp-tools.json`）。结果 run 直接 `failed`
> 「对端没有提供能力」。规则里的 `capability` 必须用**工具名**，测试里也按工具名构造能力表。

**同步补的契约字段**：`RunSummary.fast_rule`（此前只有 `RunAccepted` 有，详情接口拿不到，
违反「可追溯」要求）。

### 3.2 任务生命周期与中断

候选 run 状态：
`accepted → understanding → planning → waiting_confirmation / executing → succeeded / failed / cancelled / interrupted`。
缺参可进入 `waiting_input` 再回到理解阶段；这些是 agentd 自己的状态，不复用 robotd Task 枚举。

| 场景 | 必须发生的行为 |
| --- | --- |
| 请求被接受 | 固化输入、会话、模型配置版本，写入任务与首条事件后返回 ID |
| 多步计划 | 展示简短步骤与实际进度；计划修改生成事件，不悄悄换目标 |
| 工具返回 task_id | 记录 run / tool_call / robot_task 的关联；等待 robotd 终态而非认定完成 |
| 工具超时或断线 | 标为“执行结果待确认”，先查任务/状态；物理动作不自动重发 |
| Harness 正常退出 | 仅表示规划结束；有未确认工具/机器人任务时不能记为 succeeded |
| 用户取消任务 | 中断 Harness、取消待审批和相关 robotd 任务；有运动风险时请求 `robot_stop` |
| 软件停止 | 先直达 robotd，无模型、无审批；同时阻止该 run 后续步骤和旧授权继续执行 |
| 停止结果未知 | 显示“已请求停止，尚未确认”，不得把按钮点击当成“已停稳” |
| agentd 重启 | 活动 run 标 interrupted；旧审批不恢复可执行；对未完成 robotd 任务重新观测 |

没有自动回滚已经发生的物理动作；部分完成需要展示已完成步骤、未完成步骤与原因。
模型/网络失败可人工重试规划；是否允许安全的只读重试由工具属性决定，禁止统一重试所有工具。

### 3.3 审批与语音

正常批准遵循 [architecture.md §10.6](../architecture.md#106-后端大脑codex-harness由-agentd-管理的本地子进程)：
持久化待审批 → 系统播报动作和参数 → 播报结束后打开确认窗口 → 明确匹配的口头确认
→ 短时、一次性、capability 与参数摘要绑定的授权 → robotd 执行前校验。

UI 展示“准备询问 / 正在复述 / 等待语音确认 / 已确认 / 已拒绝 / 已超时 / 已取消”，
附动作、人类可读参数和剩余时间。正常界面**没有“全部允许”或批准按钮**；
已有 POC 人工回填仅保留在显式测试/维护模式，不能与生产授权混用。
没有可靠语音输入、审计落库失败或 robotd 尚不支持授权校验时，需审批动作保持不可用，
不退回无审批执行。系统审批播报能力是 robotd 侧协作依赖，不能用需审批的 `robot_speak` 递归实现。

## 4. 高级模型配置

### 4.1 配置对象与边界

“高级模型”指 agentd 用于理解、规划和复杂对话的模型，不是 robotd 快速检测器，
也不等于 modeld 的视觉模型。UI 同时展示三者职责，但本页只写 agentd 配置。
首版可保存多份 profile，只允许一个默认激活项；不做自动择模和静默故障切云端。

| 字段 | UI / 校验语义 |
| --- | --- |
| 名称 | 用户可读，如“本地规划”；系统生成稳定 profile_id |
| provider / 协议适配 | 只列已实现的适配器；OpenAI 兼容是协议类型，不承诺任意服务都可用 |
| endpoint / model | 默认本机端点；URL 必须校验，不允许内嵌凭证；模型 ID 可发现也可手填 |
| credential_ref | 可选凭证引用；输入只写，不回显；UI 仅见“已设置 / 未设置” |
| 数据边界 | 本地为默认；非回环/代理出口不得凭 URL 名字认定为“本地” |
| reasoning_effort | 仅适配器与模型支持时可选，否则隐藏，不伪造“高级”档位 |
| 输出 token 上限 | 正整数且不超过已知能力；能力未知时明确未知，不虚构上下文窗口 |
| temperature | 仅支持时展示；不要同时硬塞给不支持它的推理模型 |
| 请求超时 / 单任务预算 | 有限值；token/耗时预算可执行，费用未知时显示未知而非 0 元 |
| 上下文策略 | 最近对话 + 经确认的任务事实；截断/摘要行为可见，不上传全量事件日志 |

连接与协议配置由受控字段映射到 Harness；UI 不接受任意 CLI 参数、shell 命令或任意配置片段。
沙箱/工具权限不是“模型高级参数”，不能通过切模型扩大。
凭证从受支持的系统安全存储或环境变量引用读取；普通 JSON/SQLite 仅存引用。
浏览器不直接持有 provider 密钥、调用 provider 或执行本机命令。

### 4.2 本地与外部模型

项目主页仍要求所有数据本地保存，架构对“可选云端增强”留有提案。
**本设计不借模型设置页放开该约束**：首版仅激活本地 profile；云端入口可说明为“未开放”。
若后续明确批准外部模型，需要先单独记录数据边界决策，再做显式开启与授权。

后续外部模式必须说明接收方、用途和数据类型；文本、图片、语音转写分别授权，
默认不传媒体、原始日志、凭证或任意本地文件。端点改变、HTTP 重定向或代理变化不能绕过边界检查。
本地端点背后的转发/遥测也在探针中核查，不能以“localhost”标签保证数据不外传。

### 4.3 测试、保存与生效

```text
编辑草稿 -> 校验字段 -> 测试连接 -> 验证 Harness 兼容 -> 保存新版本 -> 设为默认
                                  |
                            不兼容：显示原因，不生效
```

- “测试连接”用固定、无敏感数据的探测输入，不发送用户会话、不执行机器人动作。
  分开报告：连接 / 认证 / 模型存在 / 流式 / 工具调用 / 取消 / Harness 接入；
  HTTP 200 或模型列表成功不能显示为“可用于 Agent”。
- 无兼容证据时只允许保存草稿，不能激活。记录测试时间、模型、适配器/Harness 版本与配置摘要；
  配置、凭证引用或相关版本改变即需要重新验证。
- 页面明确区分“当前默认”和“当前任务使用”。任务启动时固定配置 revision；
  修改默认不影响在跑任务，新配置从下一个 run 生效，旧版本与其凭证引用不得原地覆盖。
- 保存/激活采用 revision 乐观锁；多页冲突显示“配置已被修改”，不后写覆盖。
  生效失败保持旧配置并显示原因。回退创建新的版本/激活记录，不改写历史。
- 凭证撤销后不得为旧 run 偷换凭证或 provider：应显式失败/中断，并保留审计记录。

## 5. 用户界面设计

### 5.1 信息架构与视觉原则

导航只保留 **总览 / 任务 / 事件 / 设置**，默认进入总览；“设置”默认打开“高级模型”。
原 ESP32、robotd、视觉、音频调试页放入“开发与诊断”次级入口，保留已有维护工作流。
首版不强制更换前端框架；复用现有 HTTP/WS 能力，按产品视图拆分 UI 与调试逻辑。

浅色或跟随系统；正文用中文短句，时间/数值用等宽辅助；绿色+“正常”、黄色+“需要注意”、
红色+“故障”、灰色+“未知/离线”，不只依赖颜色。单位显式，危险操作不靠图标猜含义。
支持键盘、可见焦点与屏幕阅读器；动态摘要以低频合并通知，不能每条遥测都打断阅读。
桌面卡片双列，手机单列；软件停止入口固定可见但不遮挡内容。

### 5.2 总览：首页无需读日志

以下为**示意数据**，不代表当前真机状态：

```text
机器人                         总览  任务  事件  设置
本机连接正常 · 更新于 1 秒前                 [停止机器人]
-------------------------------------------------------
需要注意：高级模型未连接。停止与确定性指令仍可用。
                                       [查看模型设置]

当前任务
“跟随我”                         等待语音确认
已识别目标；机器人正在等待你明确确认。
步骤：识别目标 已完成 -> 语音确认 等待中 -> 跟随 未开始
[查看任务] [取消任务]

身体 robotd：在线 / 空闲       大脑 agentd：正常
语音：正在聆听                 高级模型：未连接
相机：可用                     本地视觉模型：就绪
电量：未知（无上报）           最近观测：13:53:41

输入请求：[                         ] [发送]
仅展示当前可用的指令示例；不展示未发布动作快捷键。

最近发生的事                                [全部事件]
13:53:40 等待你确认“跟随当前目标”
13:53:39 已识别跟随目标
13:52:11 高级模型连接失败，复杂任务暂不可用
```

总览先放影响使用的一个主要问题，再放当前任务、关键状态和最近 5 条语义事件。
没有活动任务时显示“空闲，等待请求”，不以最近完成任务冒充当前任务。
多个故障按安全/动作结果未知、当前任务阻塞、一般降级排序，可展开其余问题。
设备不在已发布观测中、未接入或过期时写“未知/未接入”，不伪造电量、停稳或健康。

“当前正常”不等于所有进程 alive：上方分别显示服务连接、任务与身体观测。
每张状态卡含来源、观测时间；超过 freshness 阈值改为“状态已过期”，阈值由契约声明。
WS 断线立即提示，保留最后数据但灰显；重连取得快照前不能恢复“正常”。

### 5.3 任务页：像进度记录，不像终端

列表显示：用户请求、状态、开始时间、耗时、输入来源；筛选进行中/已完成/异常。
详情包括：

| 区域 | 内容 |
| --- | --- |
| 顶部 | 原始请求、状态、当前阻塞原因、取消入口 |
| 步骤 | 已完成 / 正在做 / 等待确认 / 未开始；展开看实际工具与参数 |
| 对话 | 用户输入与 Agent 面向用户的回复；流式文本结束前标注生成中 |
| 审批 | 动作复述、语音确认窗口和结论；只读，不把点卡片当成批准 |
| 结果 | 已完成什么、未完成什么、证据来自哪个 robotd task |
| 诊断 | 可折叠的工具耗时、模型配置 revision、错误码、关联事件 |

“取消任务”是终止编排；“停止机器人”是软件安全旁路，两者语义分开。
身体停止确认前，取消中的任务不得提前写成“已安全停止”。
失败任务可“以此请求新建任务”，重新检查状态并重新审批，不一键重放历史工具调用。

### 5.4 事件页：默认是人类可读的时间线

```text
事件
[今天 v] [全部级别 v] [全部来源 v] [搜索关键词……]
[任务：全部 v]                         [暂停实时更新]
-------------------------------------------------------
今天
13:53  等待确认                              任务 #…
       机器人询问是否跟随当前目标，尚未执行。
       [查看任务] [展开详情]

13:52  高级模型暂不可用                       需要注意
       连接本地规划模型超时；复杂任务未启动。
       建议：在“高级模型”设置中测试连接。
       [打开设置] [展开详情]

13:50  已恢复与身体的连接                     已恢复
       状态已重新同步；断线期间没有自动补发动作。
-------------------------------------------------------
显示 1–50 条                             [加载更早事件]
```

- 默认展示重要业务变化，不展示 token 片段、心跳、相机每帧/每条位姿；按日期分组，
  同一故障可折叠为“连续失败 8 次，首次/最近时间”，原事件仍可查询。
- 一张卡片回答“发生了什么 / 影响什么 / 当前是否恢复 / 可以做什么”。
  恢复事件关联原故障；不把旧故障从历史里删除，也不从历史最新一条错误推导当前状态。
- 支持时间范围、级别、来源、任务和关键词；搜索覆盖可读标题、摘要与错误码。
  点击“展开详情”才显示 ID、结构化字段与脱敏原始诊断。
- 采用服务端游标分页；实时新增先显示“有 N 条新事件”，不把正在阅读的历史顶走。
  暂停实时更新只暂停 UI，不停止采集。
- 空历史显示“尚无事件”；筛选无结果显示“没有符合条件的事件”；加载失败/缺口单独提示，
  不能都显示为空列表。时间显示用户本地时区，可查看完整时间与时区。
- 中文标题来自确定性事件模板，不调用高级模型总结日志；模型离线也能读懂历史。
  未识别事件显示“未知事件类型 + 来源”，保留诊断入口，不静默丢弃。

## 6. 状态、持久化与事件

### 6.1 真相归属与重启

| 对象 | 权威 | agentd 持久化 / 展示内容 |
| --- | --- | --- |
| RobotState / robot Task | robotd | 有来源和时间的只读观测、关联 ID；不能覆盖 robotd 状态 |
| Harness 健康与 run | agentd | 生命周期、步骤、工具调用、结果与中断原因 |
| 审批 | agentd | 请求、规范化参数摘要、窗口、结论、授权审计 |
| 高级模型配置 | agentd | profile / 不可变 revision / 激活指针；仅凭证引用 |
| 语义历史 | agentd | 自身事件、外部观测事件、关联与可读投影 |

沿用总架构的 SQLite Store 方向，建议数据实体为 `sessions`、`runs`、`run_steps`、
`tool_calls`、`approvals`、`model_profiles`、`model_revisions`、`events`。
配置、审批/任务状态与对应事件在同一事务提交后才能推送，避免“页面成功、历史没保存”。
原始流式转写不是语义数据库；放入本项目 `work/` 的受控子目录，不入版本库。
Store 路径由运行配置指定，默认也在项目 `work/`；SQLite/JSON 不做双可写真相源。

外部调用无法和本地数据库做原子事务：先持久化 tool_call 意图与 ID，再调用，
最后记结果。崩溃落在两者之间时标 outcome_unknown 并对账，不把它当作未执行而重试。
授权消费的单次性由 robotd 持久/原子校验负责，不能只靠 agentd 内存标记。

### 6.2 候选事件信封

| 字段 | 含义 |
| --- | --- |
| event_id / cursor | 本地持久唯一 ID / 稳定递增查询游标，重启不归零 |
| type / version / severity | 稳定事件类型、schema 版本、info/warning/error |
| occurred_at / received_at | 来源发生时间与 agentd 接收时间，均带时区；不信任跨进程时钟完全一致 |
| source / source_instance_id / source_seq | 来源、来源进程实例与序号，用于去重和发现缺口 |
| session_id / run_id / tool_call_id / robot_task_id / approval_id | 按需关联，不用一段自由文本猜关系 |
| code / params / data | 可读模板键、脱敏模板参数与结构化证据；不存凭证和私有思维链 |
| caused_by / recovery_of | 因果和恢复关系；仅在证据明确时填入 |

候选类型包括 `run.accepted`、`run.waiting_input`、`run.step_changed`、
`run.finished`、`tool.requested`、`tool.outcome_unknown`、`approval.waiting`、
`approval.resolved`、`dependency.unavailable`、`dependency.recovered`、
`model.validation_failed`、`model.activated`、`observation.gap`。
旧 POC 事件经适配归一化；未经登记的新类型不能随意直通稳定接口。

**当前状态恢复不等于历史补齐**：robotd WS gap 后先重拉其权威 State，并记录缺口。
若上游没有事件回放能力，历史明确保留“该时间段事件不完整”，不得靠快照编造中间动作。
浏览器重连则可从 agentd 持久事件游标补读；先建立订阅缓冲，再取得带 watermark 的快照，
只应用 watermark 之后的事件并去重。游标过期返回明确错误并完整重载，不悄悄跳过。

### 6.3 容量与保留（实施前确认数值）

首版要求有界内存队列、分页上限、磁盘配额与保留策略，不能永久追加原始 token/遥测。
语义事件和审计、用户对话、原始转写分开配置保留期；具体天数/容量在首轮探针后确认，
不在此草案中擅定。清理必须给出时间范围/数量与保留边界，不让用户误以为历史无限完整。
磁盘满、数据库不可写时标记降级并禁止新审批动作；独立软件停止路径仍保持可达。
历史查询失败不得伪装成“没有事件”。

## 7. 对外接口与访问边界（候选）

agentd 面板面事实源为 `agentd/contracts/openapi.yaml`（已落地，不再是候选），
事件 schema 独立登记；实施须遵循项目现有契约规范与已接受的 ADR-0007。
以下表只定义产品所需语义，不构成第二份机器可读事实源。

| 面向 | 候选操作 | 语义 |
| --- | --- | --- |
| 存活 / 总览 | `GET /healthz`、`GET /api/state` | 自身存活；含 freshness、配置 revision 和 watermark 的聚合观测 |
| 会话 | `GET/POST /api/sessions`、`GET /api/sessions/{id}` | 会话元数据与分页消息 |
| 提交 / 中断 | `POST /api/run`、`POST /api/stop` | 保留 POC 路径；幂等提交；stop 仅为中断编排，不冒充身体停止确认 |
| 任务 | `GET /api/runs`、`GET /api/runs/{id}` | 分页列表与步骤、审批、robot task 的关联 |
| 历史 | `GET /api/events` | 时间/级别/来源/run/关键词、游标、截断/缺口标识 |
| 实时 | `WS /api/events/live` | 快照对齐后的事件推送；鉴权、背压与重连规则 |
| 模型 | `GET/POST /api/model-profiles`、`PUT /api/model-profiles/{id}` | 脱敏读取、新建或生成新 revision；乐观锁 |
| 测试 / 激活 | `POST /api/model-profiles/{id}/validate`、`POST /api/model-profiles/{id}/activate` | 有界异步测试；激活已验证的特定 revision |
| 审批观测 | `GET /api/approvals` | 可读状态与结论；UI 正常流没有批准写入口 |
| 内部审批门 | 独立受保护的请求/结论通道 | 仅供 MCP 适配器、可信语音链路；不得暴露成任意网页可批准 |
| 机器人停止 | 浏览器可信客户端直调 robotd 的 `robot_stop` | 不依赖 agentd、Harness 或模型存活；同步取消编排并吊销未用授权 |

默认仅绑定回环；回环不等于可信调用者：UI 同源托管，校验 Origin/Host，
写操作与 WS 有本机会话认证及 CSRF 防护，去掉当前 POC 的通配 CORS。
若 UI 由 agentd 托管，先加载的静态页面仍应能在 agentd 失联时直达 robotd 停止；
robotd 自己的可信调试停止入口也必须保留，不能只剩一个依赖 agentd 的网页入口。
跨端口停止的凭证/允许来源要由 robotd 契约显式支持，不通过放开任意来源解决。
高级模型配置、凭证管理、测试/激活和内部审批端点不能投影为普通模型工具。

## 8. 验收场景

| 场景 | 用户应看到 / 系统应保证 |
| --- | --- |
| 首次启动无模型 | 总览和事件可用；复杂任务提示配置；不影响软件停止 |
| 设置可用本地模型 | 分项兼容检测通过；新任务用新 revision；无真实上下文出现在探测请求 |
| 配置填错/不兼容 | 字段级原因；旧默认保持；无“保存成功即已生效”误导 |
| 高级模型失联 | 顶部显示影响；确定性路径与历史可用；不静默换 provider |
| 简单跟随请求 | 不进入 Harness；目标不明先澄清；仍须审批与 robotd 执行证据 |
| 审批到期/语音不可用 | 不执行；时间线解释“未执行，因为未获得明确确认” |
| 运行中更改配置 | 当前 run 固定旧 revision；新 run 才切换；历史可追溯 |
| 工具超时 | “执行结果待确认”；查询对账，无物理重发 |
| agentd 崩溃/重启 | 保留历史；原 run 中断；不复活动作、审批或授权；独立停止入口可用 |
| WS 断线和事件缺口 | 过期状态灰显、重连对齐；上游缺失明确标记，不编造历史 |
| 浏览历史时有新事件 | 提示新事件数量，阅读位置不跳；筛选分页无重复/漏项 |
| 隐私与权限 | UI/日志无密钥；非可信来源不能写配置/审批；未批准外传策略不能激活外部模型 |

## 9. 实施前必须取得的证据

- 本地 provider 与目标 app-server 版本是否支持工具、流式、取消、线程恢复及关闭外传；
  不通过就把复杂任务标不可用，不退回默认云端。
- robotd MCP 发现/调用的实际接入方式、审批系统播报、语音完成事件与一次性授权校验；
  这些接口缺口需在 robotd 自己的契约和任务中补齐。
- agentd 与 robotd 停止/取消的竞态：停止后旧 run 的后续步骤与尚未消费授权必须失效，
  且 agentd 不可达不应削弱 robotd 的执行前检查。
- 凭证安全存储适配方式、事件容量/保留参数；需要新依赖或结构性决策时先记录再实施。

上述证据未齐全不妨碍先做只读总览、历史和配置草稿界面，但不得宣称具备安全动作闭环。
