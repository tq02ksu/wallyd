# agentd 开发任务清单与界面交付计划

## 1. 使用方式与范围

目标行为与 UI 线框以 [详细功能与界面设计](agentd-functional-design.md) 为准。
**本清单全部任务初始为待开始**；设计文档存在不代表实现完成。
完成任务时补实现提交与 `eval/` 证据，不以“写了代码”代替端到端完成。

P0 表示契约、兼容性、安全或首版主链阻塞；P1 表示首版产品交付项；P2 为后续扩展。
阶段不是必须串行的工期估算：先以 A01/A02 探针结果调整，避免凭空排天数。
本文不负责 robotd Python 迁移；协作项通过其自身契约与
[robotd 开发计划](robotd-development-plan.md) 承接。

## 2. 任务总表

所有源码路径为**建议落点**，逐任务创建有效模块，不一次搭空目录。
保持现有 `src/agentd.ts` 为进程入口，可将内部模块逐步收敛到 `src/agentd/`；
UI 可落 `src/panel/`，不强制 React 或新增构建工具。

> **2026-10-23 实际落点（与上文建议不同，已生效）**：旧 `src/agentd.ts` 与整个 TS POC 已删除。
> 入口 `agentd/src/agentd/cli.ts`，模块同目录下 `{store,events,robotd-client,http,ws,runs,models,overview,service}.ts`；
> UI 落在 `agentd/ui/`（无构建工具，原生 ESM + CSS），由 agentd 同源托管。
>
> **agentd 与 robotd 是同一种形态的独立包，平级并列**：
>
> | robotd（Python） | agentd（TypeScript） |
> | --- | --- |
> | `pyproject.toml` | `package.json`（唯一依赖：`@openai/codex-sdk`） |
> | `src/robotd/` | `src/agentd/` |
> | `tests/{unit,contract,integration}/` | `tests/{unit,contract,integration,e2e}/` |
>
> 契约随包走（`agentd/contracts/`）；生成工具仍集中在根 `contracts/tools/`
> （一套工具产出两份契约并做交叉断言）。测试分层也与 robotd 对应：
> `tests/contract/` 补上「实现 == 契约」这半边——`contract:check` 只管「生成物 == 契约」。
>
> 状态列已按实际完成度更新：**A03–A09、A15–A18 已完成**；A10（受管 Harness）与 A13（语音审批）
> 未开始，因此 A11/A12/A14 只到「编排骨架 + 停止旁路」，尚不具备完整安全动作闭环。

## 3. 逐任务完成标准

### M0：先证明能接，再冻结接口

#### A01 现状与本地 Harness/provider 探针

- [ ] 对照 `src/agentd.ts`、`src/robot-mcp.ts` 和现有 smoke 列出现状/目标/迁移兼容矩阵。
- [ ] 固定目标 app-server 版本；实测本地 provider 的流式、工具调用、中断、线程恢复与退出。
- [ ] 使用无敏感 fixture，记录本地端点是否代理外部、Harness 是否存在额外模型调用/遥测。
- [ ] 任一必需能力失败都明确阻塞复杂任务，不用继承用户默认云端配置掩盖失败。
- [ ] 复现命令与结论进 `eval/`，原始日志进项目 `work/eval/`；探针不触发真机动作。

#### A02 robotd 协作对齐

- [ ] 明确 robotd 当前工具发现与调用入口，排除直接导入代码/读取生成文件的耦合。
- [ ] 登记目标绑定、最终 ASR、系统播报完成、确认窗口、执行授权校验等契约缺口及负责人。
- [ ] 明确 agentd 不可达时 robotd 如何拒绝新授权动作；停止如何撤销旧 run 的动作资格。
- [ ] 画出 stop 与“正在批准/已批准未执行/执行中”竞争的时序，确认不出现停止后续跑。
- [ ] 确认浏览器可信直达 robotd 停止的认证/来源边界；不以通配 CORS 解决跨端口。
- [ ] 缺口在 robotd 自己的契约任务中承接；未交付前可做仿真，但真机验收阻塞。

#### A03 agentd 独立契约与兼容策略

- [ ] 按已接受的 ADR-0007，在 `agentd/contracts/` 定义面板 API、事件、错误与生成物；
  不修改 robotd 契约来表达 agentd 状态。
- [ ] 固定 ID/时间/分页/幂等键/revision/watermark/gap 语义，统一所有错误响应。
- [ ] 区分内部审批与浏览器只读审批；模型设置端点不进入 Agent 工具面。
- [ ] 对 POC `/api/run`、`/api/stop`、`/api/state` 等逐项决定保留适配或显式版本迁移。
- [ ] 运行项目既有 `contract:generate` / `contract:check`，按需扩为双契约门禁；
  消费端生成与机器人工具投影分离，不把面板操作误生成为模型工具。
  → 落地为**三道**：`contract:check`（生成物==契约）、`agentd/tests/contract/`（实现==契约）、
  `agentd` 的 `typecheck`（实现类型==生成物类型）。第三道由 `contract:check` 盯住
  「`HarnessInfo` 是否仍从 `components['schemas']['HarnessStatus']` 派生」来防止退化。

### M1：可靠状态与历史底座

#### A04 核心模块与服务入口

- [ ] HTTP/WS、Store、Harness、观测客户端有明确启动/就绪/关闭顺序与有限超时。
- [ ] 默认回环，同源 UI；Origin/Host、写操作认证/CSRF、WS 握手权限与请求体上限一致。
- [ ] 移除产品面通配 CORS；恶意网页和模型工具都不能写配置、凭证或审批结论。
- [ ] 保留旧入口兼容适配且不扩大权限；关闭只回收本次管理的子进程。

#### A05 Store 与恢复

- [ ] schema 迁移可重复；已有数据升级先备份并有明确回退边界。
- [ ] session/run/step/tool_call/approval/profile/revision/event 建立稳定关联；
  业务状态与对应审计事件同一事务写入后推送。
- [ ] 外部调用意图先落库；崩溃中间态记为未知并对账，不自动重放动作。
- [ ] 重启保留历史、活动 run 标 interrupted、旧 pending 审批取消且旧授权不能复活。
- [ ] 数据库不可写/磁盘满时新副作用 fail closed；错误可见，不影响 robotd 独立停止。

#### A06 观测与快照

- [ ] robotd 权威 State、任务和语音事件归一化为只读投影，带来源/观测时间/新鲜度。
- [ ] 区分“未接入 / 无数据 / 过期 / 离线 / 正常”；服务 alive 不等于身体停稳。
- [ ] 上游实例变更、序号跳跃、重连重拉快照；无回放能力时记录历史缺口。
- [ ] 浏览器订阅缓冲 + watermark 快照 + 去重保证无缝对齐，慢客户端有界背压。

#### A07 语义事件与查询

- [ ] 为任务、审批、模型、依赖故障/恢复登记事件模板和明确关联。
- [ ] 可读摘要无需模型；心跳/token/每帧遥测不污染默认时间线。
- [ ] 服务端过滤、关键词搜索、稳定游标分页；相同时间事件仍无重复/漏项。
- [ ] 未知类型、无匹配结果、缺口、游标过期和存储错误各有不同返回语义。
- [ ] 探针后确认容量与保留参数；清理边界可见；查询和日志脱敏。

### M2：高级模型真正可配置

#### A08 profile 与凭证

- [ ] 运行校验、API 类型与 UI 字段来自同一配置定义，并对齐 ModuleManifest 约定。
- [ ] provider/endpoint/model/能力参数有类型约束，拒绝未知配置键与任意命令。
- [ ] profile revision 不可变，默认指针独立；凭证引用可撤销但不可原地偷换。
- [ ] 安全存储适配只写密钥；数据库、事件、错误、导出和浏览器返回均不含密钥。
- [ ] 首版只允许本地激活，未知网络出口不能按“本地”放行；不新增未获批准的外部模式。

#### A09 验证、激活与回退

- [ ] 分别检测连接、认证、模型、流式、工具、取消与 Harness 兼容，探测不含用户数据。
- [ ] 配置/凭证引用/适配器或 Harness 版本变化使旧验证失效；HTTP 200 不能代替兼容通过。
- [ ] 支持保存不兼容草稿；仅允许激活验证通过的 revision。
- [ ] CAS 防止多页覆盖；生效失败保持旧默认；回退有新的激活事件。
- [ ] 活动 run 固定旧 revision；预算/超时可执行，未知费用不写 0。

#### A10 app-server 受管适配

- [ ] app-server 版本与协议握手、启动/退出/重启上限可观测，用户不直接操作 Harness。
- [ ] session/thread/turn、流式用户回复、工具和中断映射为 agentd 自己的类型。
- [ ] 使用固定 profile，不继承不可控的默认 provider、工具或 shell 权限。
- [ ] 崩溃只中断相关 run；有限退避可重启进程，但不能自动恢复动作。
- [ ] 原始转写有界、脱敏、受控存放；不对 UI 暴露私有思维链。

### M3：可解释、可取消、可审批的任务

#### A11 输入与会话

- [ ] 文本幂等；最终 ASR 按实例/事件去重，旧事件和重复事件不触发任务。
- [ ] STOP 优先于活动任务/模型等待；已知完整指令走确定性白名单。
- [ ] 目标无法绑定、指令缺参时澄清，不猜测执行；新普通请求遇忙显式冲突。
- [ ] 快速路由与 Harness 共用权限/审批；会话恢复先刷新状态，旧证据不能直接执行。
- [ ] 路由注册表支持增量添加表达、参数规则和上下文前提；唯一完整匹配才快速执行，
  无匹配转 Harness，缺参/冲突进入澄清，不用模型置信度代替执行条件。
- [ ] 新规则有正反例、歧义/冲突回归、版本化启停与回退，事件记录命中规则 ID/版本；
  审批不得降级，STOP 优先路径不可覆盖；首版不允许模型自行写入生效规则。

#### A12 run 与执行对账

- [ ] 状态机覆盖理解/澄清/规划/等待确认/执行/终态；步骤与工具调用有稳定 ID。
- [ ] 关联 robotd task，只有实际执行证据满足目标后才 succeeded。
- [ ] 模型声称完成、进程正常退出、工具返回 accepted 均不能单独判成功。
- [ ] 超时进入结果待确认；查询对账；不自动重试副作用；部分成功如实展示。
- [ ] 请求、配置版本、步骤、工具参数摘要和失败原因在历史中可追溯。

#### A13 语音审批与授权

- [ ] 先持久化审批，再系统播报；收到播报完成才开启确认窗口；每次只激活一个 ID。
- [ ] 确认匹配动作/参数；含糊肯定、旧转写、回声、窗口外输入不能批准。
- [ ] 一次性授权绑定 capability/参数/请求者/有效期，robotd 消费端执行原子校验。
- [ ] 拒绝/超时/取消/存储或语音失败均不执行；正常 UI 无批准写入口。
- [ ] 验证 token 复用、改参、过期、重启及测试模式凭证不能绕过生产检查。
- [ ] A02 的 robotd 能力未交付则本任务只能仿真通过，不能标完成。

#### A14 停止与降级

- [ ] 软件停止直达 robotd，不等 Harness/高级模型/审批；agentd 挂掉仍有可信入口。
- [ ] 取消编排、待审批、未消费授权和相关执行任务；迟到工具结果不能触发下一步。
- [ ] 区分“请求已发送 / 已确认停止 / 结果未知”；未确认不能显示停稳。
- [ ] 模型失联、robotd 失联、Store 不可写、音频失效各有明确降级策略与用户说明。
- [ ] stop 幂等；验证停止与批准、工具提交和重连的所有关键竞态。

### M4：日常界面

#### A15 UI 壳与总览

- [ ] 总览/任务/事件/设置四入口，开发诊断次级入口保留旧面板能力。
- [ ] 总览展示最重要问题、活动任务、关键观测与最近 5 条语义事件。
- [ ] 覆盖首次启动、无模型、无活动任务、离线、过期和未接入；不编造设备数值。
- [ ] 桌面/手机布局、键盘焦点、状态文字、对比度和低干扰动态提示可用。
- [ ] 固定软件停止入口只接可信 robotd 路径；未接通时明确禁用，不能做假按钮。

#### A16 模型设置 UI

- [ ] profile 切换/新建、模型发现/手填、条件高级参数、凭证只写。
- [ ] 草稿/测试中/失败/可激活/已激活状态清楚；测试结果逐项呈现。
- [ ] 默认配置与当前任务配置分开显示，标注“下一次任务生效”。
- [ ] 修改冲突、失效测试、保存失败、凭证撤销和回退都有可理解提示。
- [ ] 外部模型未开放提示可见，不提供暗门或浏览器直调 provider。

#### A17 任务与审批观测 UI

- [ ] 可文本提交、查看会话、流式回复和步骤，输入来源与理解结果分开。
- [ ] 列表筛选、详情关联、等待原因、部分完成和结果待确认可读。
