# ADR-0002 闭环分两层——编码器读取在 ESP32、低频修正与标定在 robotd

## 背景

底盘用 42BYGH47 步进电机 + TB6600，固件（`firmware/robot_server_v2.py`）按**开环脉冲计数**
执行 `move`/`rotate`：`rate = speed × STEPS_PER_M`，发固定数量脉冲就完事。当前实现里
**没有编码器读取、没有 PID、没有丢步检测**（全库 grep `encoder/PID/odom` 为空）。

开环步进的核心风险是**丢步（step loss）**：负载扭矩超过电机输出时转子跟不上换向，**实际少转**，
而系统毫不知情——误差**永久累积**，走 10 米可能偏半米。这是"命令不是事实"在物理层的直接体现
（外部资料：机器人小车项目技术门槛咨询记录，2026-10-14，不在本项目内）。

同时暴露一个治理问题：`STEPS_PER_M = 8000.0` / `WHEEL_BASE_MM = 120.0` 目前是**固件常量**，
注释自己写着"占位值：装车后按实际标定"——意味着**每次标定都要重刷固件**，与"标定知识应在
上层、可配置、可热更新"的原则相悖。

需要决定：**闭环控制落在哪一层。**

## 决策驱动

- **硬实时约束**：脉冲时序在微秒级、不可被打断，只有固件能保证（Wi-Fi/BT 抢占会导致抖动→丢步）。
- **决策与语义**：丢步判定阈值、任务级容差、标定参数属"知识"而非"时序"，需要上下文。
- **架构纪律**：`robot-runtime.ts` 已声明分层意图「**步数=板子、位姿=Runtime**」，本决策要与之自洽。
- **实现成本**：跨串口（含 2000ms 链路巡检）做高频闭环不现实，也不必要。
- **可维护性**：标定值改一处不应触发固件重刷。

## 考虑的选项

- **A. 纯开环**：只发脉冲，不加反馈。靠加减速曲线与速度余量压低丢步概率。
- **B. 全部闭环放 ESP32（高频，1kHz）**：编码器 + PID 全在固件，robotd 只发目标值。
- **C. 全部闭环放 robotd（跨串口闭环）**：robotd 读编码器、算 PID、下发修正。
- **D. 分层：ESP32 读编码器 + 执行脉冲 + 如实上报；robotd 做低频修正（10–50Hz）、丢步判断与标定。**

## 决定

选择 **D**。理由：闭环里**只有脉冲生成与编码器采集是硬实时的**，其余全是可延迟的决策——
按"需要硬实时 → ESP32，需要上下文/决策 → robotd"这条判据切开，既拿到反馈能力，又不让高频回路
跨串口。B 把决策也压进固件（不可配置、难迭代），C 让高频回路走串口（延迟不可接受），A 则
放弃了"知道有没有走准"这一能力，无法满足精度要求。

**具体分工**：

| 职责 | 层 | 理由 |
| --- | --- | --- |
| 脉冲生成（PUL 时序） | ESP32 | 微秒级、不可打断 |
| 加减速曲线插值 | ESP32 | 属脉冲生成的一部分 |
| 步进脉冲计数（应发） | ESP32 | 发脉冲时同步计数 |
| 编码器读取（实走） | ESP32 | 中断/定时器采集，硬实时 |
| **上报「应发 vs 实走」** | ESP32 → robotd | 如实报告，不做判断 |
| **丢步判断、阈值、任务容差** | **robotd** | 决策 + 语义，不需实时 |
| **位置/速度目标级修正（10–50Hz）** | **robotd** | 慢环做决策 |
| 运动学解算（差速：轮速→车速/转向） | robotd | 身体抽象 |
| **标定值 `STEPS_PER_M` / `WHEEL_BASE_MM`** | **robotd（配置下发）** | 可热更新，改参数不刷固件 |
| 安全停车 / 看门狗 | ESP32 | 失联时本地兜底 |

## 后果

- 好：拿到"走没走准"的判断能力；标定从固件常量变为 host 可配置，改参数不重刷；与已有的
  「步数=板子、位姿=Runtime」分层意图自洽；固件保持简单（不做 PID 调参）。
- 坏：**闭环带宽低**——串口往返 + 链路巡检周期决定它只能做**分段修正**（走完一段核对一次），
  **不能**实时抗抖动；若期望伺服级平滑会失望。需要新增编码器硬件与接线。
- 中性：协议需扩展——`hello` 已上报 `steps_per_m`/`wheelbase_mm`，方向要从"板子报给 host"
  改为"host 配置板子"（新增配置命令），并新增编码器计数与偏差字段。

## 怎么验证

- **开环基线**：先量当前开环的重复精度（同指令走 N 次，编码器测实际位移的离散度），
  作为"是否需要闭环"的判据——见 `eval/`（待补实测记录）。
- **丢步可观测**：给一段已知里程，断言 robotd 能报出 `|应发 − 实走|`，且差异超阈值时进入告警/重走。
- **标定不刷固件**：改 `STEPS_PER_M` 后无需重刷，`hello`/状态回读应反映新值。
- **慢环语义**：修正动作只在段边界发生（符合 `TASK_STALL_MS` 的"不盲目重发"哲学）。
