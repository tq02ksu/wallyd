# GH-11：语音确认通道（`waiting_confirmation` 的唯一批准入口）

状态：实现中。对应 issue：`[V08] 语音确认通道：把 waiting_confirmation 走通（唯一批准入口）`。

## 边界

用户没有屏幕、键盘或手臂；输入只有语音与摄像头。因此：

- 批准**只能**来自 `speech.final`；`/api/approvals` 保持只读，不加任何写方法或按钮；
- robotd 只做「一次性凭据校验」，不判断「用户是否同意」（凭据校验已在 #18 落地）；
- 本 issue 只改 agentd 侧：持久化审批、播报后开窗、语音 settle、签发凭据、执行/取消。

`GET /api/approvals` 与 `/healthz` 的 `test_mode.allow_manual_approve` 用于证明
「正常界面没有写入口」，不是批准通道。

## 状态机

```
approval.status: persisted -> announced -> waiting -> approved | denied | timeout | cancelled
run.status:      accepted  -> ...       -> waiting_confirmation
                                             | approved -> executing -> succeeded | failed
                                             | denied   -> cancelled
                                             | timeout  -> cancelled
```

窗口由 `RunService.openConfirmationWindow()` 在 `speech.tts_finished`
（且 `played` 未被明确报为 0）之后打开；`transition('waiting_confirmation')` 仍拒绝
任何带审批记录的 run，防止绕过复述与窗口因果顺序。

## 判据与事件命名

issue 正文与维护者评论把「被忽略的确认」写作 `approval_ignored`、把过期写作
`approval.expired`。本仓库事件类型统一用 `category.action` 形式，因此实现为：

| 语义 | 事件类型 | 关键参数 |
| --- | --- | --- |
| 窗口过期 | `approval.expired` | `approval_id`, `action_label`, `expired_at` |
| 这句没被采纳 | `approval.ignored` | `approval_id`, `reason`, `utterance_id?` |
| 已裁决 | `approval.resolved` | `approval_id`, `action_label`, `status`, `decided_by` |

`approval.ignored.reason` 枚举：`expired` / `before_window` / `echo` / `unrecognized`。

维护者更正 2 已定：**审批记录的 `status` 用架构文档的 `timeout`**（不是 `expired`）；
事件 reason 用 `expired` 描述「窗口过期」这个理由。`ApprovalStatus` 契约枚举同步改为
`timeout`，UI 标签同时兼容旧的 `expired` 字符串。

## 判定谓词（可测）

`classifyApprovalUtterance(text)` 先做 NFKC、去首尾空白与句末标点：

- **否定优先**：出现 `不用` / `不要` / `取消` / `算了` / `不行` / `不必` / `拒绝` /
  `别` / `不确认` 任意一个 → `deny`（即使同句也有「确认」）；
- 明确肯定：出现 `确认` / `执行` → `approve`；
- 泛化肯定 `好` / `好的` / `可以` / `行` / `嗯` / `对` → **不批准**（架构 §10.6：含糊肯定不能批准）；
- 其余 → `none`，保持等待并记 `approval.ignored {reason:"unrecognized"}`。

只用 `speech.final`；桥不订阅、也不消费 `speech.partial`。

## 规则 6：只认「窗口开启之后才开始」且非回声的一轮

agentd 的 `RobotdEventBridge` 记录每个 `utterance_id` 的 `speech.started`：

- `started_at`：robotd 事件 envelope 的 `timestamp`；
- `aec_erle_db`：robotd 新增的可选事实字段（见下）；
- `during_tts`：该轮开始时 agentd 是否仍处于 `speech.tts_started` 之后、
  `speech.tts_finished` / `speech.tts_cancelled` 之前。

settle 顺序（任何一步不通过都**不改状态**，只写 `approval.ignored`）：

1. 没有 `speech.started`、或 `started_at <= window_opened_at` → `before_window`；
2. `during_tts === true`，或 `aec_erle_db` 存在且 `< 6 dB` → `echo`；
3. 文本判定 `none` → `unrecognized`；
4. `deny` → 审批 `denied`，run `cancelled`（`blocking_reason = "denied"`）；
5. `approve` → 审批 `approved`，run `executing`，由服务层签发凭据并调用 robotd。

### 回声事实字段

`contracts/events.json` 的 `speech.started` 增加可选 `aec_erle_db: number`。robotd 的
`AudioRuntime` 从桥的 `aec_echo_probe` 事件记下最近一次 ERLE（1 秒内有效），
在 `speech.started` 上如实上报。**判定门限只存在于 agentd 的 settle 一处**；
V02 落地 `speech.gate.verdict` 后，这里改为消费 verdict，不再读 ERLE
（settle 的输入已经是 `echo: boolean`，`runs.ts` 不直接读 ERLE）。

## 超时

- 默认窗口 60 秒（`ApprovalAnnouncer` 的 `windowMs` 默认值）；
- 开窗时在 `RunService` 内 arm 一个 `unref()` 定时器；到点把审批置 `timeout`、
  run 置 `cancelled`（`blocking_reason = "expired"`），写 `approval.expired` 与 `run.finished`；
- settle 时再次比较 `window_closes_at`，防止定时器丢失 / 事件乱序；
- 过期后的「确认」不改变任何状态，只写 `approval.ignored {reason:"expired"}`；
- 启动对账把上次残留的 `persisted/announced/waiting` 审批作废（`cancelled`，
  `decided_by = system`），并计入 `daemon.recovered.cancelled_approvals`。

## 凭据签发（agentd 侧）

批准后由 `approval-credential.ts` 签发 #18 定义的 `X-Wally-Approval`：

- `args_digest` 复用 `contracts/tools/approval-digest.mjs`，只覆盖能力契约的
  `approvalParams`，不另写规范化；
- payload `{issuer:"agentd", capability, args_digest, issued_at, expires_at, nonce}`，
  60 秒有效（≤ robotd 的 300 秒上限）；
- 用 `ensureApprovalSigningKey()` 的共享秘密做 HMAC-SHA256，签名覆盖 payload 段的
  原样 ASCII 文本；
- 秘密缺失 / 签发失败 → run `failed`，**不调用** robotd（fail closed）。

`RobotdClient.callCapability` 增加可选的审批头；`tool_calls` 记录
`requires_approval = true` 与 `approval_id`，供判据 1 核对。

跨语言守卫：`agentd/tests/integration/approval-cross-check.mjs` 在 integration lane
用 TS 签发、再交给 robotd 真实的 `robotd.approval.enforce_approval` 校验；
同时断言「换参数被拒」与「同一 nonce 重放被拒」，防止两侧摘要/签名实现漂移。

## 明确不做

- 不做 UI / HTTP 批准入口，不做信任白名单，不做多点确认；
- 不在本 issue 重做 robotd 凭据校验（#18 已做）；
