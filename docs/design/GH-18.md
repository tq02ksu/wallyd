# GH-18 设计记录：robotd 的审批拒绝侧

状态：已实现（拒绝侧）。签发侧在 #11，语音确认通道也在 #11。

## 边界

用户没有屏幕、键盘或手臂，只有语音与摄像头。robotd 拿不到语音通道，因此它**不能**
回答「用户同意了吗」。它只回答一个问题：

> agentd 有没有为**这组参数**放行过，而且**只用过一次**？

所以本设计只做三道门里的第三道（校验），不签发凭据、不决定哪些参数进入摘要、不开确认窗口。

## 凭据传输

需审批请求携带单行 HTTP 头：

```http
X-Wally-Approval: <base64url(payload-json)>.<base64url(hmac-sha256(secret, payload-segment))>
```

- 第一段是 UTF-8 JSON 对象，字段固定为：

  ```jsonc
  {
    "issuer": "agentd",
    "capability": "robot_speak",          // 必须等于 operationId
    "args_digest": "sha256:9f3c…",        // 见 contracts/approval-digest.json
    "issued_at": "2026-11-07T08:00:00Z",  // RFC3339，必须带时区
    "expires_at": "2026-11-07T08:01:00Z",
    "nonce": "3f9a2c…"                    // 一次性；8–128 个 [A-Za-z0-9_.:-]
  }
  ```

- 第二段是 HMAC-SHA256，**签名覆盖第一段的原样 ASCII 字节**，不是重新序列化后的 JSON。
  这样两端不需要再约定一份「凭据 JSON 规范化规则」；`args_digest` 的规范化仍然只由
  `contracts/approval-digest.json` 决定。
- `secret` 是 32 字节（64 位小写 hex）的共享验签秘密。
- 凭据有效期上限 300 秒，允许 5 秒时钟偏差。超出上限直接拒绝，不做「可配置的宽限」。

契约在三个需审批操作上声明了该请求头（`components.parameters.ApprovalCredential`）；
`robot_stop` 不声明、也不需要凭据。

## 共享秘密：零人工的信任根

| 项 | 约定 |
| --- | --- |
| 路径 | `<app-data-root>/robot/agentd/approval-signing-key` |
| app-data-root | macOS `~/Library/Application Support`；其他平台 `$XDG_DATA_HOME` 或 `~/.local/share` |
| 写入者 | 只有 agentd（`ensureApprovalSigningKey()`，首次启动自动生成） |
| 权限 | `0600`，目录 `0700` |
| 读取者 | robotd，**每个需审批请求重读一次，不缓存** |

`WALLY_APP_DATA_DIR` 只是测试隔离/显式布局的覆盖，两边读同一个值；生产不需要设置。

启动顺序：robotd 可能先于 agentd 启动。秘密文件不存在时，需审批请求一律
`403 E_APPROVAL`（`reason: missing_signing_key`），但 robotd **正常启动**、`robot_stop`
与其余端点不受影响。agentd 稍后写出秘密后，robotd **无需重启**即可校验新凭据。

## 已消费 nonce：robotd 自己的小账本

| 项 | 约定 |
| --- | --- |
| 路径 | `resolve_work_dir(config) / approval-nonces.json`（默认 `<项目根>/work/`） |
| 内容 | `{"version": 1, "consumed": {"<nonce>": <consumed_at_epoch>}}`，**不存凭据本体** |
| 写入者/读取者 | 只有 robotd |
| 何时写 | 验签、参数摘要、有效期全部通过后，**执行前**；写成功才算消费成功 |
| 清理 | 每次写入顺带删除 `consumed_at < now - 24h` 的记录，不做定时任务 |
| 崩溃一致性 | 读写失败（包括目录不可写、已有文件损坏）→ 拒绝请求，绝不「记不上先执行」 |

秘密与账本**分开放**：`work/` 是可清理的运行产物目录，秘密放进去会被 `git clean`
或运维清理带走；反过来把 nonce 账本放进应用私有目录，又会让可清理的运行时数据
永久堆积。

写入使用「同目录临时文件 + `fsync` + `os.replace`」，进程内用一把锁保证
check-then-consume 原子（`ThreadingHTTPServer` 是多线程的）。

## 校验顺序

1. 缺 `X-Wally-Approval` → 403（`missing_credential`）；
2. 读共享秘密，缺失/非法 → 403（`missing_signing_key`）；
3. 验签（失败统一 `bad_signature`，不区分「格式坏了」与「签名不对」）；
4. `issuer == agentd`、`capability == operationId`；
5. 时间：`issued_at` 不在未来、`now <= expires_at`、窗口不超过 300 秒；
6. 用 `robotd.approval_digest.approval_args_digest(body, approval_params)` 复算并与
   `args_digest` 比对（`approval_params` 来自能力表，已由契约一致性测试锁住）；
7. nonce 未消费 → 原子落盘；已消费 → 403（`nonce_replayed`）。

错误体固定为 `403` + `E_APPROVAL`，`message` 说明「该能力需要 agentd 签发的一次性授权」，
`details.reason` 给出上面这些稳定原因，便于排障时区分「没凭据」与「凭据无效」。

## `--debug` 不豁免

`--debug` 只多开 `/v1/debug/*`。审批门不读取 `debug`、没有开关、没有环境变量旁路——
排障手段是日志、事件流与摄像头画面，不是绕过审批。

## 交给 #11 的接口

签发侧只需要：

1. 读取同一个共享秘密（`ensureApprovalSigningKey()` 已保证存在）；
2. 按上面的 payload 字段与 `approvalParams` 计算 `args_digest`；
3. 用**同一段 base64url 文本**做 HMAC，生成两段式头；
4. 每个 nonce 只签一次，短时有效。

本 issue 不实现步骤 1 的签发逻辑、不决定哪些参数进入摘要、不开确认窗口。
