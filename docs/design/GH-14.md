# GH-14 语音回归基线

## 1. 目标与边界

`docs/voice-architecture.md` §11 定了 11 项门槛，但此前没有任何一项能重复跑：
`eval/r14-voice-bringup-2026-10-24.md` 全是单次手工取证。本设计把其中 **6 项**
变成一条命令可复跑、可判红、可回溯的基线；剩下 5 项（CER、端点误切/漏切、
说话人归属、人物跟踪、运动安全）**不在本链路**，原因写在 `eval/voice/README.md`。

边界（与 #9 并行，避免撞车）：

- 只新增 `eval/voice/`、`Makefile`、根 `package.json` 的手动目标与 `.gitignore`；
- **不改** `robotd/`、`agentd/` 的源码，**不改** `contracts/`；
- 基线读桥的 stdout NDJSON，不新增事件契约；
- 只**测量**，不修判定逻辑。测出来不达标就如实标红，不许顺手降门槛或删指标；
- 需要真机的项不进 push CI（`scripts/ci/run-gates.sh` 不变）。

## 2. 六项指标与测量口径

| 指标 | §11 | 离线 `--file` | 真机 | 口径 |
| --- | --- | --- | --- | --- |
| 首字延迟 | 800ms | ✅ | ✅ | 音频轴：首个 `partial.audio_end_ms` − VAD 开口 `audio_ms` |
| ASR 最终延迟 | 1500ms | ✅ | ✅ | file：`endpoint.silence_ms` + finalize 墙钟尾巴；mic：墙钟静音→final |
| TTS 首包 | 800ms | ❌ | ✅ | `tts_chunk_started[0]` − `tts_started`（进程内单调时钟） |
| 打断响应 | 300ms | ❌ | ✅ | 用户开口 → 停止播放；两侧事件必须同一进程 |
| 自听误触发率 | 0 | ❌ | ✅ | 播放期 VAD 判开口次数 |
| 采集连续性 | 30 分钟 | ❌ | ✅ | `--trace` feed 心跳最大间隔 + 序号单调（代理阈值 2s） |

**为什么首字/最终用音频时间轴**：`mac_speech.swift` 的 `--file` 分支灌数据比实时快得多，
墙钟会把「说多久才出字」压缩成「ASR 算多快」，5s 与 60s 夹具不可比。事件自带
`audio_ms` / `audio_end_ms` / `silence_ms`，正好给出与喂入速度无关的基准点。
纯静音到 EOF 会吐一个空文本 `final` 信封，所以 D 类判据是「有文本的 final = 0」。

## 3. 夹具

`eval/voice/fixtures/**/*.json` 是唯一入库的夹具文件；音频由脚本在缺失时现场合成
（幂等），`.caf/.wav/.generated.json` 全部 gitignore。

| 夹具 | 来源 | 守什么 |
| --- | --- | --- |
| `a_single_zh_5s/15s/60s` | synthesized | 首字延迟与句长无关；最终延迟 |
| `b_two_speakers` | synthesized（两个 zh 音色交替） | 多人轮流下的延迟稳定性；**不是真人，不测说话人归属** |
| `d_silence_10min` | synthesized（标准库写 16bit WAV） | 不产语音 final |
| `c_barge_in` | **pending-hardware**（只有标注，无音频） | 打断/AEC 场景登记；#41 落地 |

必填字段固定为 `fixture / kind / duration_ms / source / expected{utterances,texts} / notes`。
本仓库增加的**可选** `generate` 段只描述「怎么生成」，目的是让「新增场景 = 加一个 JSON」成立，
无需改脚本：`generate.segments[]`（每段一段音频，按序跑完即 A→B→A→B）或
`generate.silence_ms`。`source` 三态：`synthesized` 可自动合成；`recorded` 绝不自动生成；
`pending-hardware` 不许有音频，旁边出现 `.caf/.wav` 直接校验判红（防拿假 CAF 冒充真机）。

## 4. 判定与基线

- `eval/voice/baseline.json` 入库。首次由真机 `--seed-baseline` 写入，**与运行报告同构**
  （同一份 JSON + `seeded: true`）；SKIP 的指标保留但 `p95 = null`，不参与相对回归。
- `--seed-baseline` 与 `--replay-dir` 同时出现会被拒绝（退出码 2）：合成事件不能洗成硬件基线。
- 每次判定两条同时生效、**取严**：§11 绝对值；`(本次 p95 − 基线 p95)/p95 > 20%`。
- `--repeat 2`（默认）在同一台机、同一次会话内连跑，额外检查两次 p95 波动 ≤ 20%
  （对应验收判据 3，只对能离线测的首字/最终两项有意义）。
- 退出码：0 全 measured 且全过；1 有 FAIL；2 夹具/参数/工具链错误；3 有 SKIP（不完整但报告可用）。
- 报告自检（`validate_report`）拒绝 `status=pass`、拒绝 skipped 带 verdict、拒绝 measured 无样本，
  保证「把 SKIP 改成 PASS」这类改法会直接判红。

## 5. 已知限制与偏差（如实记录）

1. **`--file` 仍要求麦克风授权。** `scripts/mac_speech.swift` 的 `stream` 在解析 `--file`
   之前就 `micAuth()` 判权限，所以「无麦克风授权」的 Mac 上离线车道同样起不来。
   脚本如实标 `SKIP — needs-mic-permission`。issue 管理侧评论假设「`--file` 在任何 Mac
   （含无授权）都能测」，与代码不符——见 Q1。
2. **采集连续性没有帧序号。** 桥不吐逐帧计数，只能解析 `--trace` 的 feed 心跳（≈1s/行）：
   相邻心跳 >2s 视为疑似断流，feed 序号必须单调。长采集同时把 `--idle-timeout` 调大，
   否则安静房间 20s 就被空闲超时收尾。报告 `threshold_source` 已注明它是仓库代理阈值。
3. **TTS 首包含进程启动。** `tts_started` 在进程启动时发出；常数项，用于回归可比，
   但不要与外部工具数字硬比。
4. **环境噪声未量化**（issue 明确不做实验室级标定），报告记 `ambient_db: null`。
5. **replay 不是证据。** `--replay-dir` 只服务单测与演示，报告标 `host.replay=true`、
   `device.source=replay`，摘要写「合成事件，不是硬件证据」。

## 6. 待人工确认

- **Q1**：是否允许把 `mac_speech.swift` 的 `micAuth()` 检查移到 `filePath == nil` 分支
  （一行），让离线 `--file` 真正不依赖麦克风授权？本轮按「只新建」边界未改。
  具体改法：把 `let filePath = opt("--file")` 提到权限检查之前，并写成
  `if filePath == nil, micAuth() != "authorized" { fail(...) }`（删掉后面重复的那行）。
- **Q2**：本 worktree 所在执行机是 Linux，没有 macOS/swift/声卡，因此 6 项全部 SKIP、
  `baseline.json` 只能以未播种状态入库，判据 3（两次波动 < 20%）与「贴两次完整 JSON +
  注入退步」的证据必须在 Mac 上补跑。是由人工在 Mac 上播种，还是给一个 macOS runner？

| # | 判据 | 状态 | 落点 / 证据 |

| 1 反 | 无参数、不清缓存也能自建夹具 | ✅（静音已实测；语音需 Mac 合成） | `generate_clip()` / `--generate-only`；`test_generate_only_writes_silence_wav_on_linux` |

## 8. 本轮证据

- `python3 -m unittest discover -s eval/voice/tests`：60 项纯逻辑单测通过（含「翻倍注入 → FAIL」、
  「SKIP 改成 PASS → 判红」、「pending-hardware 带 CAF → 判红」、feed 心跳不单调 → FAIL、
  模拟已授权 Mac 的 2 measured / 4 SKIP）。
- `sh eval/voice/run_baseline.sh`（本机）：6 项全部 `SKIP`、退出码 3、JSON 与摘要完整 ——
  证明「缺硬件不 PASS 也不崩」。
- `sh eval/voice/run_baseline.sh --replay-dir eval/voice/tests/data`：6/6 measured、退出码 0，
  仅用于验证管线，**不作为硬件证据**。
