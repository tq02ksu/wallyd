# GH-53：审批复述的安全词表与「再说一遍」

状态：已实现（契约 + 词表 + robotd 校验/渲染 + agentd 生成/重播）。
对应 issue：审批是唯一能批准物理动作的通道，而用户只能用耳朵接收复述；
任何「听起来模糊」的内容都会变成误批或无谓的重复询问。

## 问题

`POST /v1/robot/announce`（GH-19）已经堵住了「免审批版 `robot_speak`」的洞，但
`args_summary` 仍是 1–200 字的自由字符串。TTS 对 `0.15` 可能读成「零点一五」「点一五」
或「零点十五」；对 `2m` 可能读成「两米」「二 m」。审批链路是单向一次的，ASR 侧纠错
救不回一句用户本来就没听清的话。

## 决策

### 1. `contracts/announce-lexicon.json` 是唯一词表

词表把以下规则写死，robotd 与 agentd 都读它，**不各写一份**：

- `args_summary.max_chars = 60`、`max_fields = 4`；
- 数字 → 中文读法（`0.15` → `零点一五`，`30` → `三十`）；
- 整数按标准普通话音节读：`10` → `十`、`19` → `十九`；万位低位组保留
  「一十」（`10015` → `一万零一十五`），只有最高位组省略前导「一」；
- 单位 → 中文词（`m` → `米`，`m/s` → `米每秒`，`cm` → `厘米`）；
- 字段 → 标签（`max_distance_m` → `最远距离`）；
- 禁用不确定词（`大约` / `左右` / `略微` / `一点点` …）；
- `repeat.max_attempts = 3`。

实现：

- TS/Node：`contracts/tools/announce-lexicon.mjs`（附 CLI `announce-lexicon-cli.mjs`）；
- Python：`robotd/src/robotd/announce_lexicon.py`。

跨端测试 `robotd/tests/contract/test_announce_lexicon.py` 用同一输入逐字节比对两端输出，
覆盖 `0..200` 全区间与 `10000/10015/100000/1000000` 边界，并把词表复制到临时文件、
只改一个数字读法，断言两端输出**同时变**。

### 2. `args_summary` 的格式约束在契约层

`AnnounceRequest` 增加 `x-announce-lexicon: announce-lexicon.json`，`args_summary`
`maxLength` 收敛到 60，`kind` 枚举增加 `approval_unheard`。robotd 对每条摘要执行词表校验，
以下情况一律 `400`，**不会交给 TTS**：

- 超过 60 字或超过 4 个参数项；
- 含 `大约` / `左右` / `略微` / `一点点` 等不确定词；
- 含未按词表读法的阿拉伯数字（`0.15`、`2.0`、`1e-3`）；
- 含全角/罗马等非 ASCII 数字字符（两端解析必须一致）；
- 含英文单位缩写（`m/s`、`cm`）；
- 含控制字符/换行。

agentd 的 `formatArgsSummary()` 从能力契约的 `approvalParams` 生成摘要。字段没有词表读法、
值超出精度、拼不下 60 字时，`executeFastRun` 以
`args_summary_unrepresentable` 收尾并说明「未执行」，而不是压缩成一句听不清的话。

### 3. 「再说一遍」是显式 `repeat` 意图

`classifyApprovalUtterance` 增加 `repeat`：`再说一遍` / `没听清` / `什么` 等命中它。
否定仍然优先（`确认不用` → deny）；`repeat` 在疑问句与肯定词判定之前、在否定之后。

确认窗口内收到 `repeat`：

- `repeat_count` 原子加一（落库，重启不清零），写 `approval.repeat_requested`；
- 由 `ApprovalAnnouncer.reannounce()` 重播**同一条** `approval_repeat`；
- 审批仍 `waiting`，`approval.resolved` 不新增，`window_opened_at` / `window_closes_at` 都不变；
- 窗口过期仍按**原始** `expires_at` 算，重播不会延长窗口。

第 4 次（`max_attempts + 1`）按「没听清即不执行」收尾：审批 `denied`、
`approval.resolved {status: denied, reason: repeat_limit}`、run `cancelled`，并由
`ApprovalAnnouncer.announceUnheard()` 走系统播报念固定句
「我没有听清，这次没有执行。」（`kind=approval_unheard`，仍无自由文本）。

### 4. 复述与确认之间要有可闻边界

固定模板尾缀改为「请说确认。」；robotd 的 `AnnounceAccepted.text` 能看到它，
短摘要时 agentd 的 `speech.spoken.excerpt` 也能看到。`speech.spoken` 新增可选的
`approval_id` 与 `kind`，即使摘要较长、80 字 excerpt 被截断，事件里仍能观测到
「这是审批复述 / 收尾提示」。

## 与 #49 的合入顺序

#49 会给 `robot_announce` 增加 `kind=clarification` 并把 `AnnounceRequest` 改为
discriminated union（PR #54 尚未合入 main）。本分支按 main 的当前形态做**加法**：
`kind` 枚举增加 `approval_unheard`，不引入第二个自由文本口。两者都改 `AnnounceRequest`
时以先合入者为准，后合入者需要把 `approval_unheard` 并入 union 的对应分支；
词表与 repeat 逻辑不依赖 `clarification`，可以独立保留。

## 明确不做

- 不做语音自助纠错（「你刚才是不是说 0.5 米？」）——那会把一次审批变成两次；
- 不给 `robot_announce` 加 `text` 字段；
- 不做多音色/方言适配；
- 不追求 TTS 逐字节可复现。
