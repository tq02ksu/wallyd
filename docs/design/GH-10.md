# GH-10 Harness 执行器：thread 与会话解耦，codex-home 隔离可证

## 1. 目标与边界

`route: 'harness'` 的 run 目前停在 `accepted`，Harness 从未真正执行。本轮只做「接线」，
不重写 run 状态机，也不把模型 SDK 塞进 `runs.ts`：

- `run-request.ts` 对称增加 `executeHarness(runId)`，与 `executeFast` 同一装配层；
- 新增 `agentd/src/agentd/harness.ts`：执行器只依赖注入的 `HarnessClient` 接口，
  单元测试用假客户端跑完整生命周期；
- 新增 `agentd/src/agentd/harness-codex.ts`：唯一 import `@openai/codex-sdk` 的适配层；
- `runs.ts` 保持纯状态机 + SQLite：`grep -n codex agentd/src/agentd/runs.ts` 零命中。

不做：多 thread 并行、跨会话记忆、改 `codexHomePath()` 位置、改 `router.ts`、新增 `harness.*`
事件类型。

## 2. thread 与会话解耦

`sessions` 表新增 `thread_id`（schema v2 → v3，走 `MIGRATIONS` + `SCHEMA_VERSION`，迁移前备份）：

```text
sessions(session_id, title, status, thread_id, created_at, updated_at)
```

执行流程：

1. `session_id` 有 `thread_id` → `resumeThread(thread_id)`；
2. 没有 → `startThread()`；
3. 收到 `thread.started`（或 turn 结束后 `thread.id` 非空）→ 把 id 写回该 session；
4. `resumeThread` 在首个 turn 失败且错误形如「找不到 thread/rollout」→ 新建 thread **重试一次**，
   并显式留痕；不静默假装续上。

无 `session_id` 的 run 每次新建 thread，不持久化（首版明确不做跨会话记忆）。

### 重建留痕：不新增事件类型

`agentd/contracts/events.json` 没有登记 `harness.*`。按仓库纪律不自行扩事件契约，重建写成：

- 一条 `run.step_changed`（`step_title = "重建 Harness 线程"`，`data.note = "harness.thread_rebuilt"`，
  附 `previous_thread_id` / `thread_id`）；
- 一条 raw jsonl 记录 `{"type":"harness.thread_rebuilt", ...}`；
- 一条结构化日志。

这样「明确记录」与「事件白名单不扩张」同时成立。

## 3. codex-home 隔离

子进程环境由 `buildCodexEnv()` 显式构造并传给 SDK：

```ts
{ PATH, HOME?, CODEX_HOME: codexHomePath(), CODEX_API_KEY }
```

SDK 一旦收到 `env` 就不再继承 `process.env`，因此主机 `~/.codex` 不出现在子进程环境里。
`codexHomePath()` 仍是 `~/Library/Application Support/robot/agentd/codex-home`
（可用 `AGENTD_CODEX_HOME` 覆盖 CI/测试），不落到 `work/` 或 `Caches`。

隔离验证分两层：

- 单测：`buildCodexEnv()` 的键集合只含白名单，不携带 `process.env` 的其他变量；
- 取证：`agentd/tests/integration/codex-probe.mjs`（`npm run test:codex`）用主机 `~/.codex`
  **文件集合**跑前/跑后精确 diff，不比 mtime/计数。无 `CODEX_API_KEY` 时跳过真实 turn，
  但隔离断言照跑。

## 4. 事件过滤

thread 原始事件（`thread.started`、`item.*`、`reasoning`、`turn.*`）只写：

```text
<dataDir>/harness/<run_id>.jsonl
```

默认 `dataDir = work/agentd`，即 issue 要求的 `work/agentd/harness/`。写入 `EventLog` 的只有：

| 内容 | 落点 |
| --- | --- |
| run 状态迁移 | `run.step_changed` / `run.finished` |
| 工具调用 | `tool_calls` 表（`recordToolCall`）+ `run_steps` 行 |
| 最终结论摘要 | `runs.result_summary` + `run.finished.detail` |

执行阶段映射：`accepted → planning`（开始 turn）→ `executing`（首个 `mcp_tool_call`）
→ `succeeded`（`turn.completed`）。失败停在 `failed`，并在 `run_steps` 里标出失败阶段。

## 5. 取消与超时

`RunService.cancelRun` 仍只改状态；新增 `onCancel(runId)` 钩子，事务提交后由装配层调用
`HarnessExecutor.abort(runId)`。执行器按 `run_id` 保存 `AbortController`，其 `signal` 直接传入
`Thread.runStreamed(input, { signal })`，SDK 会杀掉子进程。

- 用户取消：run 已是 `cancelled`，执行器捕获 abort 错误后**吞掉**，绝不转成 `failed`；
- 执行器超时：默认 120s，abort 后 `failed {reason:"harness_timeout"}`；
- 关闭进程：`dispose()` 中止所有活动 run。

## 6. 工具面边界

执行器不向模型提供 robotd HTTP 直连：

- `networkAccessEnabled: false`、`webSearchMode: 'disabled'`；
- `sandboxMode: 'read-only'`、`approvalPolicy: 'never'`、工作目录是 `<dataDir>/harness/workspace`；
- 不在 `config` 里注册任何 MCP server。将来由 `robot-mcp` 适配器以 stdio MCP 挂进
  `mcp_servers`，模型只能看到 robotd 已发布的工具面。本轮不实现该适配器，也不新开 HTTP 口子。

`mcp_tool_call` 事件已按「工具名 + 参数 + 结果」映射到 `tool_calls` / `run_steps`，适配器落地后
无需再改执行器。

## 7. 未配置凭证

`CODEX_API_KEY` / `OPENAI_API_KEY` 都没有时**不 spawn**：

```text
run.status = failed
run.blocking_reason = harness_unconfigured
detail = 缺少 CODEX_API_KEY 或 OPENAI_API_KEY，复杂指令暂不能交给 Harness
```

`--harness` 缺失或路径不存在同样归为 `harness_unconfigured` 并说明缺什么。
假 key 会继续走到 SDK，失败原因不是 `harness_unconfigured`，以此区分「没配」和「配错」。

## 8. 验收映射

| # | 判据 | 自动化 |
| --- | --- | --- |
| 1 | `--harness` 后 `brain.harness.state == ready`、`harness_bridge` pass | `computeHarnessStatus` + `ModelService.validate` 单测 |
| 2 | 多步指令 `planning → executing → succeeded`，步骤/工具可读 | 假 Harness 客户端单测 |
| 3 | 同 session 两个 run 复用 thread；换 session 不同 | 假客户端单测（断言两个 run_id 不同） |
| 4 | 取消 <1s，终态 `cancelled` 不是 `failed` | 假客户端阻塞 turn + `cancelRun` 单测 |
| 5 | 主机 `~/.codex` 文件集合 diff 为空 | `npm run test:codex`（无 key 也跑隔离断言） |
| 6 | 无 key 不崩，`failed {reason:"harness_unconfigured"}` | 执行器单测 |
| 7 | schema v2→v3 迁移，旧库可开且有备份 | `store.mjs` 迁移测试 |

真 codex 二进制 + 真凭证的端到端（判据 2/3/4 的实现侧）在无网络/无 key 环境记录为
`not-run`，不以假客户端结果冒充真机验证。
