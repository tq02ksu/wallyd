# GH-63 person.* 事件族与可选 speaker_id

## 1. 目标与边界

本 issue 只建立**事件事实面**，让 #50 后续的绑定与 `interlocutor` 有地方挂：

- `agentd/contracts/events.json` 登记 `person.appeared` / `person.moved` / `person.lost`；
- `person.moved` 的频率上限写在**契约**里（`rate_limit`），由事件入口执行；
- `speech.utterance_heard` 补**可选** `speaker_id`，未实现时省略；
- 生成物用工具重生成，`npm run contract:check` 通过；`person.*` 不进入模型工具面。

不做：不接 Vision、不写跟踪/IoU、不做声纹识别、不出现 `person.identified` /
`person.recognized` / `person.bound`、不做绑定与 `interlocutor`、不定义
`speaker_1` / `speaker_2` 的编号规则、不碰摄像头或麦克风。全部可离线验证。

## 2. 决策

### 2.1 person.* 只登记在 agentd，robotd 保留前缀预留

`agentd/contracts/events.json` 是 agentd 的事件白名单，登记后 `EventLog.emit`
不再以「未登记」拒绝这三条（判据 1）。

robotd 侧**不**把三条写进 `events[]`：`events[]` 是「已实现、有 `_reduce`
分支或显式 `no_state`」的精确名单，而检测与跟踪尚未实现。robotd 的登记表已有
`reserved_unimplemented: people.* / person.*` 前缀预留，未来发布端实现时可以直接
emit；把三条登记成 `no_state: true` 会让 `WsHello.supported_event_types` 提前
宣称支持一个不存在的发布者，属于未验证的能力声明。发布端登记与 `_reduce`/`no_state`
归属留在后续检测/跟踪 issue。

### 2.2 字段形状

| 事件 | 必填字段 |
| --- | --- |
| `person.appeared` | `track_id`（string）、`bbox`（object）、`first_seen_at`（string, UTC ISO 8601） |
| `person.moved` | `track_id`、`bbox` |
| `person.lost` | `track_id`、`last_seen_at`（string, UTC ISO 8601） |

`bbox` 是 `{x, y, width, height}` 四个数值字段。**坐标系与单位（归一化或像素）
由发布端实现在后续 issue 中确定**：本 issue 没有权限替跟踪实现选坐标系，只保证
字段存在、类型明确、可被下游引用。

`track_id` 只表示「同一条跨帧 track」，不表示「同一个人」；这是观测事实与身份判断的
边界（`person.lost` 之后 track 失效，引用它的绑定必须作废）。

### 2.3 person.moved 的频率上限是契约，不是注释

`person.moved` 在契约里声明：

```json
"rate_limit": {
  "max_hz": 5,
  "window_ms": 1000,
  "key_field": "track_id",
  "excess": "drop",
  "note": "同一 track 在任意 1000ms 滑窗内最多 5 条。超出的观测直接丢弃，不排队、不补发……"
}
```

- 生成器把 `rate_limit` 原样写进 `agentd/contracts/generated/events.json`，并校验
  `max_hz > 0`、`window_ms` 为正整数、`key_field` 指向 payload 字段、`excess=drop`、
  `note` 非空；
- `EventLog.emit` 是唯一入库入口，按契约执行滑窗限流（`event-rate-limit.ts`）。
  超出的观测返回 `throttled: true`，**不写库、不补发**——位置流要的是最新值，
  补发旧位置只会撑大事件库；
- 限流状态按进程内存保存（重启清零），契约描述的是「入库上限」，不是持久配额。

“位移小于阈值不发”属于跟踪实现的语义，不在本 issue；本契约只给硬上限。

### 2.4 speaker_id：可选、省略、不编号

同一事实在两端各声明一次，类型一致（string，可选）：

- robotd 的**生产侧**：`contracts/events.json` 的 `speech.final.payload.speaker_id`；
- agentd 的**消费侧**：`agentd/contracts/events.json` 的
  `speech.utterance_heard.payload.speaker_id`；
- agentd 的 OpenAPI 里与 utterance 元数据同处：`RunRequest.asr_meta.speaker_id`
  （可选；`speech.utterance_heard` 本身没有逐字段的 OpenAPI schema，
  `WsEvent.payload` 是开放对象，事件形状的唯一机器可读定义是事件登记表）。

约定：未实现时**省略**字段；填 `null` 或占位串会被 payload 校验拒绝
（下游必须能区分「没有这个事实」与「事实为空」）。编号规则与
「说话人 ↔ track」的绑定语义属于 #50 第二段，本契约不定义 `speaker_1` / `speaker_2`。

`robotd-event-bridge.ts` 只在 `speech.final` 真的带 `speaker_id` 时透传，
不做任何推断。

### 2.5 新增 payload 字段级校验

登记表本来就声明了 `type / required / enum`，但 `EventLog.emit` 过去只检查类型是否
登记。`event-payload.ts` 把这些声明变成可执行校验，`emit` 在写库前拒绝缺必填字段、
类型不符、枚举外取值与「可选字段填 null」。这是判据 2 里「契约校验」的实现，
同时也让 `speaker_id` 的「可选」在运行时真实成立。

启用校验后暴露了三处既有的契约漂移，一并修正（都是 payload 缺 `approval_id`）：

- `runs.ts` `cancelRun()` 的 `approval.resolved`；
- `runs.ts` `abortApproval(byStop)` 的 `approval.resolved`；
- `runs.ts` `abortApproval(other)` 的 `approval.unavailable`。

## 3. 验证记录

| 判据 | 命令 | 结果 |
| --- | --- | --- |
| 1 | `node --experimental-strip-types agentd/tests/unit/person-events.mjs` | pass；打印实际 emit 的 JSON 原文（见下） |
| 2 | `node --experimental-strip-types agentd/tests/contract/event-payloads.mjs` | pass；含反向判据（把 `speaker_id` 改必填 → 不带它的 payload 校验失败） |
| 2（全链） | `node --experimental-strip-types agentd/tests/unit/speaker-id-chain.mjs` | pass；`speech.final` 带 `speaker_id` → `utterance_heard` 原样透传；不带/空串 → 字段省略（撤掉桥的透传后该测试变红） |
| 3 | `npm run contract:check` | pass；手改 `agentd/contracts/generated/events.json` 一行后变红（见下），`npm run contract:all` 后恢复绿 |
| 4 | 同一 unit 测试的 60s 模拟 | 30Hz × 60s = 1800 条输入 → 入库 **300** 条（5.00Hz） |
| 5 | `event-payloads.mjs` + `contracts/tools/check.mjs` | `mcp-tools.json` 不含三条事件；agentd 端点不得进工具面的既有断言仍绿 |

实际 emit 出来的一条事件原文（`person.appeared`，测试输出；`event_id` 与时间戳是运行时值）：

```json
{"event_id":"ev-boot-per-mwbvynqm-1","type":"person.appeared","severity":"info","occurred_at":"…","received_at":"…","source":"robotd","payload":{"track_id":"t-1","bbox":{"x":0.25,"y":0.1,"width":0.2,"height":0.3},"first_seen_at":"2026-11-11T08:00:00.000Z"}}
```

手工改一行生成物后的门禁输出（随后已用 `npm run contract:all` 重新生成）：

```text
FAIL agentd/generated/events.json 与手工编辑的契约不一致；先跑 npm run contract:agentd
```

把 `speaker_id` 临时改成 `required: true` 后（随后已恢复并重新生成）：

```text
  FAIL speaker_id 不是必填
  FAIL speaker_id 声明为可选
  FAIL 不带 speaker_id：契约校验通过 ["speaker_id 必填但缺失"]
3 项失败
```

60 秒模拟的条数输出：

```text
输入 1800 条（30Hz × 60s）→ 入库 300 条 → 5.00Hz
```
