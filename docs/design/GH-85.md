# GH-85 move_distance / ActionEpisode 机器可读契约

## 问题

现有契约只有任务查询、取消、暂停与恢复，没有 `submitTask(move_distance)` 的入口；
`Task` 只有生命周期状态，没有动作回合（ActionEpisode）与结果（TaskResult）的投影。
ADR-0014 要求把「受理」「动作结束」「物理达成」分账：HTTP 200、板侧应答、
`motion.done` 都不能单独证明目标达成。本轮只发布契约、生成物与契约测试，
不实现 Task Executive、串口、运动控制或 Safety Word。

## 范围

- `contracts/openapi.yaml`：`POST /v1/tasks`、`TaskSubmitRequest` / `MoveDistanceRequest`、
  `TaskHandle`、`TaskFeedback`、`ActionEpisode`、`TaskResult`，以及 `Task` 投影上的
  `episode` / `result` 两个可选字段；
- `contracts/events.json`：`motion.done` / `motion.aborted`、`task.*` 与 `safety.*` 的
  `episode_id` 关联、`stop_confirmation` 语义块；
- 生成物（`contracts/generated/*`）与两侧契约测试（Node + Python）；
- 能力/路由的**最小接线**：`task_submit` 显式登记为未实现，路由返回
  `503/E_UNAVAILABLE`，不伪造 `task_id`。

## 决定

### D1 `submitTask` 是任务资源上的语义操作，不是设备原语

`POST /v1/tasks`，`operationId: task_submit`。请求按 `action` 判别，M0 只有
`move_distance` 一个变体。参数只接受带单位后缀的 SI 字段：

- `distance_m`（米，必填，`x-unit: m`，±0.3 米、绝对值 ≥0.05 米、不得为 0）；
- `speed_mps`（米/秒，可选，默认 0.15，0.05–0.4）。

`additionalProperties: false`，因此无单位的 `distance` 直接 400；handler 也会给出
明确错误文案。范围来自文档化的手动驾驶步长/速度（0.05–0.3 米、0.05–0.4 m/s），
更细的 Runtime Guard 由 #87 负责，本轮不发明硬件限值。

### D2 `TaskHandle` 只是引用

响应 200 的 schema 是 `TaskHandle`：`{task_id}` 且 `additionalProperties: false`。
它不含进度、状态、`goal_achieved` 或 `evidence`。读状态用
`GET /v1/tasks/{task_id}`；进度/事件用事件流。HTTP 200 只表示已受理。

幂等键是可选请求头 `Idempotency-Key`（进程内有效，不持久化）：同一 key + 相同参数
返回同一个 `task_id`，不新建任务、不发第二个 `task.started`；同 key 不同参数
`409/E_STATE`。资源占用 `409/E_BUSY`；未实现/未就绪 `503/E_UNAVAILABLE`；
链路不可用 `503/E_LINK`。都不排队。

### D3 三层记录与状态

| 概念 | 契约位置 | 状态 |
| --- | --- | --- |
| `TaskHandle` | 提交响应 | 只有引用 |
| `RobotTask`（公开投影 `Task`） | `GET /v1/tasks/{id}`、列表 | `TaskState`：accepted / running / paused / completed / failed / cancelled |
| `ActionEpisode` | `Task.episode`（可选） | `episode_id`、`action`、`started_at`、`finished_at`、`outcome`（completed / failed / cancelled / interrupted，open 时 null） |
| `TaskFeedback` | 事件投影（`task.progress` 等） | `task_id`、`episode_id`（可选）、`state`、`progress` |
| `TaskResult` | `Task.result`（仅终态出现） | `lifecycle` + `goal_achieved` + `evidence` |

`TaskResult.lifecycle` 是终态投影，不是 `TaskState` 的别名：`accepted` / `running` /
`paused` 不是合法结果；`interrupted` 表示被安全停止、抢占或设备丢失打断，
而 `cancelled` 表示调用方取消。映射写在 `TaskResult.x-task-result-policy` 里。

### D4 `lifecycle` / `goal_achieved` / `evidence` 分账

机器可读策略挂在 `TaskResult` schema 上（`x-task-result-policy`）：

- `goal_achieved: true` 只允许 `evidence: sensor_verified`；
- `failed` / `cancelled` / `interrupted` 时 `goal_achieved` 必须是 null；
- `evidence` 的强弱顺序是 `unknown < board_reported < sensor_verified`；
- `motion.done` 对应的结果固定为 `{lifecycle: completed, goal_achieved: null,
  evidence: board_reported}`。

三个 invariant 以名字列出，Node 契约测试逐条执行，所以策略不能只写在散文里。

### D5 事件与 ActionEpisode 的关联

- `motion.done` / `motion.aborted` 新增，payload 必带 `task_id`、`episode_id`、
  `action`、`evidence`；`motion.done` 的 `evidence` 只允许 `board_reported`，
  **不允许出现 `goal_achieved`**；`motion.aborted` 带稳定 `reason`。
- 既有 `task.*` 事件增加可选 `episode_id`（当前实现尚未产生，故不设为必填；
  #86 实现 ActionEpisode 收尾后改为必填由那一轮的契约变更决定）。
- `safety.stop_requested` / `safety.stopped` 增加可选 `episode_id`，用于把安全停止
  关联回被打断的动作回合。
- 本轮两个 motion 事件标 `no_state: true`：还没有实现消费它们；#86 接入
  Task Executive 时同时移除该标记并加 `_reduce` 分支（事件登记表测试双向锁死）。

### D6 没有 `id` 的串口 stop 不产生板侧确认

`contracts/events.json` 新增 `stop_confirmation` 机器可读块：

- `states: [requested, confirmed, unknown]`，与 `safety.stop_requested.state` 和
  `/v1/robot/stop` 响应的 `state` 枚举同源；
- `confirmed_requires: board_stop_reply_with_matching_request_id`：只有带同一
  request id 的板侧应答才能升到 `confirmed`；
- `write_success_is: requested`：串口写成功最多是 `requested`；
- `unaddressed_stop: {request_has_id: false, max_state: unknown, allowed_states:
  [requested, unknown]}`：无 id 的 stop 没有可匹配的应答，上限是 `unknown`，
  不得报 `confirmed`，也不得据此宣称物理静止。

`safety.stopped` 仍然只表示停止动作发生，不表示物理静止。

### D7 不扩大 Codex 工具面

`task_submit` 在契约里标 `x-mcp-exclude: true`，能力表用新的 `mcp_exclude` 标记，
所以 `contracts/generated/mcp-tools.json` 仍是 17 项，没有 `robot_move` 或任何设备原语。
进入 curated tool surface 由 #86 连同实现显式决定，不因内部模块/HTTP 路由自动投影。

## 判据映射

| 判据 | 证据 |
| --- | --- |
| 契约能表达 `submitTask(move_distance, distance_m=0.3, speed_mps=0.15)` 并返回 `task_id` | `contracts/tools/task-contract.test.mjs` 用 openapi-backend 校验请求与 `TaskHandle` 响应 |
| 拒绝缺失单位、错误状态、伪造物理完成 | 同一测试的负例（`distance`、缺 `action`、`lifecycle: running`、`goal_achieved: true` + `board_reported`） |
| `motion.done` 不推出 `goal_achieved=true` | 事件登记表断言 payload 无 `goal_achieved`；策略断言 `motion_done_implies.goal_achieved = null`；结果校验负例 |
| 生成物一致、`npm run contract:check` 通过 | `node contracts/tools/generate.mjs` + `npm run contract:check` |
| 不新增设备原语 / `robot_move` 工具 | `check.mjs` 断言 + `robotd/tests/contract/test_action_contract.py` 检查 mcp-tools.json |
| 无 id stop 不产生确认语义 | `stop_confirmation` 块 + 两侧契约测试断言 `write_success_is=requested`、`unaddressed_stop.max_state=unknown` |

## 不做

不实现 Task Executive、fake Motion、串口、心跳、Safety Word 或运动控制；
不碰真机与固件；不引入 ROS 2/DDS；不改变现有任务的公开行为。

## 已知残留

- `task_submit` 路由目前返回 503/E_UNAVAILABLE；`Task.episode` / `Task.result`
  在实现投影里还不会出现。契约测试只证明形状与策略，不证明运行行为。
- `task.*` 的 `episode_id` 暂为可选，避免契约声称实现未产出的字段；#86 收尾时收紧。
- `motion.done` / `motion.aborted` 还是 `no_state`，没有运行时消费者。
