## 2. 信号接线（推荐共阳接法）

| TB6600 端子 | 接到 | 说明 |
| --- | --- | --- |
| `PUL+` / `DIR+` / `ENA+` | +5V（三个 + 端并联） | 共阳：光耦驱动电流由 5V 提供 |
| `PUL−` | ESP32 GPIO（左驱 `9`） | 拉低一次 = 走一步，**低电平有效** |
| `DIR−` | ESP32 GPIO（左驱 `10`） | 高/低决定正反转 |
| `ENA−` | ESP32 GPIO（**每台一条**，2026-10-05 定） | 悬空 = 常使能（静止也一直吃电流）；拉低 = 脱机省电。**四台各占一脚**、灌电流十几 mA，可直驱不加三极管，见 §2.2 |

- 为什么选共阳：TB6600 输入是光耦（设计按 5V），共阳时 ESP32 只负责把引脚拉到 GND
  （灌电流约十几毫安，ESP32-S3 单脚可承受约 40mA）；共阴时靠 3.3V 高电平点光耦，
  电流偏小（约 8mA 量级），容易时好时坏。
- 共阳的残余电流风险：GPIO 输出高电平 3.3V 时，光耦两端仍有约 1.7V，理论上可能漏电导致
  误走步。**实测若出现电机自抖动/误动作**，在 GPIO 与 `−` 端之间串一只 1N4148 即可彻底关断。
- 5V 那一路必须与 ESP32 **共地**，否则共阳接法不成立。
- 两台 TB6600 的 `PUL`/`DIR` 各占一组 GPIO，互不共用。
- **两批板子都是共阳/低电平有效**：第一批（六端款）靠"三个 `+` 端并到 5V"实现；
  第二批的公共端从 **`OPTO`** 引脚引出，`OPTO` 接 5V 即可，见 §2.1。所以本节原则两批通用。

### 2.1 两批板子混用：`OPTO` 公共端的单端款

**现象**：丝印上没有 `+` / `−` 之分，只有 `PUL`、`DIR`、`ENA`，外加一个 **`OPTO`** 端子。
这叫**单端输入**——三个光耦的公共端在板内接到了一起，从 `OPTO` 引出来，所以
**没有"三个 `+` 端并联到 5V"这回事，也不要把 5V 灌到 `PUL` 上**。

**`OPTO` 是什么**：该引脚的内部定义是**三个输入光耦的阳极公共端**（StepperOnline 官方帮助文档
明确写：带 `OPTO` 端子的驱动器，`OPTO` 内部接所有输入光耦的阳极，按**共阳**设计）。
所以 **`OPTO` 接 +5V**，信号端由控制器**拉低**触发。

| 板上的丝印情况 | 怎么接 | 有效电平 |
| --- | --- | --- |
| **`PUL` `DIR` `ENA` + `OPTO`（本批实物）** | **`OPTO` → +5V**；`PUL`/`DIR` → GPIO；`GND` → ESP32 GND；`ENA` → 经 NPN 汇聚后接 GPIO | **低电平有效**（拉低走一步；`ENA` 拉低 = 脱机，见 §2.2） |
| 只有 `PUL` `DIR` `ENA`，无任何公共端子 | `PUL`/`DIR` → GPIO；`GND` → ESP32 GND；5V 不用接 | 先按低电平有效试（板内多为共阳） |
| 公共端子是 `GND` / `COM−` | 该端子接 GND；`PUL`/`DIR` → GPIO | 高电平有效（3.3V 高点光耦，见下） |

**`OPTO` 极性怎么复核**（断电，万用表二极管档）：红笔接 `OPTO`、黑笔接 `PUL`，
读到明显正向压降（1.0–1.5V 量级，或比反向小得多）→ `OPTO` 是**阳极**，接 +5V；
反过来读数大/开路，说明是阴极侧（接 GND，高电平有效）。

**混批兼容（好消息）**：`OPTO` 款与第一批六端款**逻辑完全一致**——都是共阳/低电平有效。
所以两批板子可以共用同一套脉冲与方向极性，固件里**不用为它单独取反**；
要取反的只有电机接线接反导致的转向。

**`OPTO` 必须接 5V，不能接 3.3V**：光耦限流电阻按 5V 设计，3.3V 供不出足够电流。
而 ESP32 在这里只负责把 GPIO 拉到 GND（灌电流），正是它的强项，所以这套接法对 3.3V 友好。

**3.3V 的坑**（只有万一是"高电平有效"那种才需要看）：

- 低电平有效（灌电流）对 ESP32 天然友好，3.3V 直接接没问题；
- 高电平有效时靠 3.3V 去点亮按 5V 设计的光耦，电流可能只有 8mA 量级 → **不动 / 时好时坏**。
  遇到就在信号线上加一级 NPN（2N2222）或用 74HCT245 拿 5V 去点，别拿 3.3V 硬怼。

**通电前 30 秒判定**（先不接 `ENA`，悬空 = 常使能；电流档取保守值、细分 1/8）：
低速发 20 个脉冲（1–2 Hz）看反应——**完全没反应**先检查 `OPTO` 有没有接到 5V、是否已共地；
**转向反了**取反方向极性；**嗡嗡抖着不转**是相序问题（对调同一相的两根）。

> 另：两批板子的**拨码细分/电流表可能不同**，按各自外壳丝印设，别互抄。

## 3. 功率与电机接线

> 三组线怎么分、每根线插到哪个端子、电机 4 根线怎么排出 A/B 两组，见
> [[wiring-connectors|接线端子与防呆规划]]「步进电机 ↔ 驱动器怎么接」的接线图与对照表；
> 本节只讲参数与注意。

| TB6600 端子 | 接到 | 说明 |
| --- | --- | --- |
| `VCC` / `GND` | 电机动力电源（9–42V） | 台面用 12V；线单独走，就近并 100–470µF 电解 |
| `A+` / `A−` / `B+` / `B−` | 电机两组线圈 | 万用表两两测通断找出同组；接反只影响转向 |

- 42BYGH47 是 4 线两相电机：两两导通的两根为一组线圈，分 A 组 / B 组接入。
- 电机线出厂带杜邦 4pin（2.54），TB6600 是螺丝端子 → 剪头压线，或用杜邦转端子转接。
- 母线电压越高，高速扭矩越好：12V 可用，若后续要提速可换 24V（TB6600 支持 9–42V）。

## 4. 拨码与电流设置

- `SW1–SW3`：细分（常见 1 / 2 / 4 / 8 / 16 / 32）。建议从 **1/8** 起（200 步 × 8 =
  1600 步/圈），兼顾平滑与脉冲频率。
- `SW4–SW6`：输出电流（常见 0.5–4.0A）。按电机铭牌额定值取档，42BYGH47 通常在 1.5A
  上下，**不要超过额定电流**；先按 1.0–1.5A 档保守试跑。
- 脉冲频率估算：1600 步/圈、5 转/秒 = 8000 Hz。

## 5. ESP32 侧要点

- **引脚避让**：GPIO26–32（Flash/PSRAM）、GPIO33–37（本板 N16R8 为 Octal PSRAM，被占用）、
  GPIO0/3/45/46（strapping）、GPIO19/20（USB）、GPIO43/44（UART0）；**GPIO48 被板载
  WS2812 占用**。稳妥选「位置连＋序号连」的连续块（如 `4·5·6`、`15·16·17`、`9–14`）。
- **脉冲生成**：不要用 `delayMicroseconds` 软循环硬怼；用定时器中断或 RMT/MCPWM 发脉冲，
  Arduino 侧可用 FastAccelStepper（底层走 RMT/MCPWM），比 AccelStepper 稳得多。
- **加减速**：0.55 N·m 带约 2kg 车体，突然启停基本必丢步，必须走加减速曲线，从低加速度
  调通再往上加。

## 5.5 ESP32 引脚分配（2026-10-05 定案：每台驱动器 3 脚）

> **引脚口径以 [[electrical-architecture|电气系统架构]] §5.2 为准**，本表与它同步。
>
> ⚠️ **两态制（2026-10-05 实测，硬性）**：本批 TB6600 的三根输入线（`PUL`/`DIR`/`ENA`）
> **只允许两种状态**——**拉低 = 有效**、**高阻（悬空）= 无效**。
> **绝对不要用"拉高到 3.3V"当无效**：此时光耦两端仍有 ~1.7V，会**部分导通**，
> 输入一直停在"有效"态 → 驱动器**永远看不到边沿、电机完全不走**（本 POC 为此排查了很久，
> 表现为"电平看着都对、手工点 GND 能走、接上 ESP32 就不走"）。详见 §2.3。

按 §5 避让原则（GPIO26–37 为 Flash/PSRAM、GPIO0/3/45/46 strapping、GPIO19/20 USB、
GPIO43/44 UART0、GPIO48 WS2812），并按「**位置连＋序号连**」重排：

| 用途 | GPIO | 接到 TB6600 |
| --- | --- | --- |
| 左驱 STEP / DIR / ENA | **9 / 10 / 11** | 左 TB6600 `PUL−` / `DIR−` / `ENA−` |
| 右驱 STEP / DIR / ENA | **12 / 13 / 14** | 右 TB6600 `PUL−` / `DIR−` / `ENA−` |
| 步进3（扩展）PUL/DIR/ENA | 4 / 5 / 6 | TB6600 #3 |
| 步进4（扩展）PUL/DIR/ENA | 15 / 16 / 17 | TB6600 #4 |

> **当前接线状态（2026-10-09）**：**左右两驱都已接**（左驱 `9/10/11`、右驱 `12/13/14`），
> 固件 `DRIVERS_PRESENT = ("L", "R")`。扩展两台未接。
> ⚠ 加驱动器时**必须同时改这个元组**：不在里面的驱动器，固件从不配置它的 `ENA` 引脚，
> 引脚停在**高阻=悬空**，而本批板「悬空 = 使能（有保持电流）」——表现就是该驱动器
> **永不自动脱机、一直发热**（2026-10-09 右驱接上后踩到）。

- 脉冲生成用 **`machine.bitstream`**（MicroPython 标准固件**无 RMT**，`machine.RMT` 不提供；
  确认 `machine.PWM`/`machine.Timer`/`bitstream` 可用）。bitstream 传 **四元组 timing**
  `(high_ns, low_ns, high_ns, low_ns)`，data 用 `0xAA` 交替位 → 每 bit 一个 high-low 周期 =
  一步脉冲，精确控步数。写入 projects 脚本 `robot_server_steps.py`。
- 低速先跑（避免丢步），加减速后置；TB6600 手册要求**脉冲宽度 >1.2us**、**方向信号先于
  脉冲 >5us**（驱动里已预留 `time.sleep_us(10)`）。

### 5.6 M1 固件与调试脚本（2026-09-2x 归档）

M1（「接入 TB6600 替换真实动作」）对应的固件与调试脚本已收进
[scripts/README](../scripts/README.md)，实现在 `machine.bitstream` 上精确控步数：

| 脚本 | 作用 |
| --- | --- |
| `robot_server_steps.py` | **M1 主固件**：TB6600 步进版指令服务器，`move`/`rotate` 发真实脉冲 |
| `upload_steps.py` | 上传该固件到板子 `main.py` 并回读长度校验 |
| `interrupt_repl.py` | Ctrl+C 中断板子循环、验证回到 REPL（烧录前置动作） |
| `test_bitstream.py` / `2` / `3` | 探针：逐步确认 `bitstream` 的**data 与 timing 正确写法** |
| `test_timer.py` / `test_timer_step.py` | 备选：用 `Timer` 周期回调翻转 STEP 引脚 |

**调试结论（关键踩坑）**：
- MicroPython 标准固件**无 RMT**，`machine.RMT` 不提供；可用的是 `PWM` / `Timer` / `bitstream`。
- `bitstream` 的 data **必须是 bytes**（`bytes([0b10101010]) * n`），传 Python list 会失败；
  timing 要传**四元组** `(high_ns, low_ns, high_ns, low_ns)`。
- 每个 bit = 一个 high-low 周期 = 一步；`0xAA` 交替位天然给出 50% 占空比。
- 主固件参数：**细分 1/8（1600 步/圈）**、脉冲半周期 5 µs（100 kHz，远高于 TB6600 的
  >1.2 µs 下限）；低速先跑，加减速曲线后置。
- **已知未完善**：`stop` 未真正中断阻塞中的 `bitstream` 脉冲；左右电机脉冲目前顺序发、
  非真正同步。详见 [脚本集 README](../scripts/README.md)「注意事项」。

## 6. 供电需求（台面测试）

| 电压 | 给谁 | 建议规格 | 必需 |
| --- | --- | --- | --- |
| 12V（DC 9–42V） | TB6600 的 `VCC`/`GND`，即电机动力 | 12V 5A（两台电机各按 1.5A 估） | 是 |
| 5V | TB6600 的 `PUL+/DIR+/ENA+` 共阳端；ESP32 的 `5Vin` | 12V→5V 降压模块，1–3A | 是 |
| 3.3V | 板载 LDO 自产，也是 GPIO 电平 | 不需要单独准备 | 否 |

最省的组合是**一个 12V 电源 + 一个 12V→5V 降压模块**（两种电压齐备）。

三条注意：

1. **必须共地**：12V 电源 GND、5V GND、ESP32 GND 连在一起。
2. **不要让 ESP32 和电机共用同一路 5V**：电机启停的压降与反电动势容易把 MCU 拉到复位。
   调试期 ESP32 直接插电脑 USB 最稳，TB6600 的 5V 从 12V 降压走；注意 **`5Vin` 是纯输入**
   （见 [[esp32-s3-n16r8-dev-board]]），别从板子取 5V，也别同时接电脑 USB 和外部 5V。
3. **通电时绝对不要插拔电机线**：TB6600 这类驱动带电断线容易炸管。

> **地线具体怎么接**（GND 汇流排、星形单点、ESP32 用 USB 供电时那根必接的共地线、
> 接完怎么用万用表验）见 [[wiring-connectors|接线端子与防呆规划]]「地线怎么接」。

## 7. 整机供电与扩展余量

- 装到机器人本体上不需要另加电源：直接取既有的 **12V 母线**（坞站 24V→12V 或电池
  18.5V→12V），再挂一个 12V→5V 模块给逻辑供电，见 [[power-architecture]]。
- 后续会扩展**水泵**、**1–2 个云台**这类负载，原电源预算未包含它们；12V 母线与 5V/6V
  逻辑轨的余量核算见 [[power-architecture]] §10「扩展负载与余量」。
- **端子系统与防呆**：动力（12V）与信号（5V/3.3V GPIO）必须用不同型号插头物理防呆，
  未来扩展按「电源 + 信号」双插头接口预留，详见 [[wiring-connectors|接线端子与防呆规划]]。
- **扩展步进**：再扩展 2 个步进（共 4 个）的引脚分配与限制见
  [[electrical-architecture|电气系统架构]] §5；4 轴**同时**动需换硬件发脉冲，逐个动不用换。

### 2.2 步进脱机 EN（2026-10-04 新增）

**为什么**：TB6600 静止时仍按拨码档持续供电流维持保持力矩。42BYGH47（约 1.5A / 单相 1.8Ω）估
每台 ≈ 8W，两台 8–19W @12V，与 M4 Mac mini 空闲 ~7W 同量级——车停着不动时步进是最大静置负载。

**怎么接**（本项目**每台一条**：电机控制 = `PUL/DIR/ENA` × **4 台 = 12 脚**，
每台各自一个 3 连排）：

```text
 段①  4 · 5 · 6 │ 7 │ 15 · 16 · 17 │ 18 │ 8
      步进3 3 连排  单  步进4 3 连排   单   单

 段②  9 · 10 · 11 │ 12 · 13 · 14
      底盘左驱 3 连排  底盘右驱 3 连排

 驱动器        PUL  DIR  ENA
 底盘左驱       9   10    GPIO11
 底盘右驱      12   13    GPIO14
 步进3（扩展）   4    5    GPIO6
 步进4（扩展）  15   16    GPIO17
```

> 为什么这样排：**每台驱动器一整盘线**（三根相邻、走同一根线束），且底盘两驱占了全板唯一一段
> 「位置连＋序号连」的 6 连排（`9–14`）。代价是底盘两驱的 `PUL/DIR` 从已接的 `4/5`、`6/7`
> 挪到 `9/10`、`12/13`（四根重插）；扩展两台未接线，零成本。

- **一驱一脚，不需要三极管**：每台驱动器的 `ENA` 独占一个 GPIO，有效时灌电流十几 mA，
  在 ESP32-S3 单脚能力内（推荐 ≈20mA / 绝对 40mA）。**不要把两台并到一脚**（会到 20–30mA+）。
- **上电/复位默认态**：引脚默认高阻 → `ENA` 悬空 → **使能/持有**（车不会自由滑行）；
  空闲省电由固件主动「拉低 = 关输出」实现。
- **固件时序**（板侧状态机，上层不碰 EN）：使能（置高阻）→ 等 10–20ms → 发脉冲 →
  发完留 100–200ms → 拉低脱机。策略与代价（无编码器 → 空闲被推动会静默丢位姿）见
  [[electrical-architecture|电气系统架构]] §5.3。

### 2.3 两态制：为什么"拉高"不能当无效（2026-10-05 实测，血泪）

**现象**：固件把 `PUL−` 空闲拉高（3.3V）、发脉冲时拉低，电平用万用表量都"对"；
但电机**完全不转**。而**把 ESP32 的信号线整根拔掉（= 真悬空）后用一根杜邦线把 `PUL−` 点 GND，它立刻转**。

**原因**：共阳接法下 `OPTO` 是 +5V，信号线拉到 3.3V 时光耦两端仍剩 **≈1.7V**——
不足以点亮，但**足以部分导通**。于是驱动器看到的是一个"一直有效"的输入，
**永远等不到"无效→有效"的边沿**，一个脉冲都不认。

| 信号线状态 | 光耦 | 驱动器看到的 |
| --- | --- | --- |
| 拉低（0V） | 完全导通 | **有效**（PUL = 一个脉冲；DIR = 一个方向；ENA = 关输出） |
| **高阻 / 悬空** | 完全不通 | **无效**（这才是可靠的"关"） |
| **拉到 3.3V** | **部分导通** | **≈有效** → PUL 永远不会翻边沿、DIR 方向不定、ENA 也关掉 |

**所以固件侧的铁律**：`PUL` / `DIR` / `ENA` **只允许"拉低"与"高阻"两态，永不打高**。
MicroPython 里就是 `pin.init(Pin.OUT, value=0)`（有效）与 `pin.init(Pin.IN)`（无效）交替。

**产品化建议（比高阻更稳）**：高阻态抗干扰差、且每步要切引脚模式（实测最高约 3.5k 步/秒）。
要做得干净，用**一只 NPN/N-MOS 做开漏**、并把信号线经 **1kΩ 上拉到 +5V**：
导通 = 拉低（有效）、截止 = 被 5V 拉到光耦完全不通（无效）——两态都明确，抗干扰也好。
若换 **TMC5160** 这类现代驱动（3.3V 逻辑直连、standstill 电流衰减、StallGuard），这些坑一并消失。
